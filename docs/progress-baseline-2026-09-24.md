## 2. 当前整体位置

Icarus 当前处于本地 TUI 技术预览阶段，已经形成以下基础使用链路：

```text
启动服务 → 打开 TUI → 创建或恢复 Session → 提交任务
→ 模型决策与工具执行 → 展示结果 → 保存会话 → 退出后恢复并继续对话
```

长期记忆通过自建 Mem0 接入，知识资料通过自建 OpenKB 接入。两者已有独立 Web 页面。
Icarus 统一 WebUI、桌面 GUI，以及会话之外的持续环境感知、主动判断和主动行动，尚未形成完整产品能力。

当前同时存在三类后续工作：

1. 已有 Agent、会话和工具能力的可靠性与体验补齐。
2. Mem0、OpenKB 已有 Web 前端的产品体验改造。
3. Session 外感知与主动反应能力的设计和验证。

三类工作的相对优先级仍需共同确认，不能把本清单中的全部待办视为下一阶段承诺。

## 3. 已实现的部分

| 模块 | 已实现内容 | 需要保留的边界说明 |
| --- | --- | --- |
| 模型与 Agent 核心 | OpenAI、Anthropic 协议适配；无状态 ReAct 执行；同步、异步及流式入口；模型与工具多步循环 | 长任务质量、完整请求预算和响应终止语义仍需完善 |
| Plugin 基础设施 | Manifest 发现、依赖解析、Capability 与 Tool 注册、生命周期、状态恢复 | 已加载 Session 的配置与插件拓扑保持稳定；单次 Run 内工具不热更新 |
| 多会话运行时 | AgentRuntime 管理多个 SessionRuntime；创建、恢复、卸载、空闲清理；会话实例隔离 | 当前主要执行环境仍以 Session 为边界 |
| Gateway | 本机 WebSocket JSON-RPC；会话与任务操作；公共 RuntimeUpdate 推送；历史读取 | Gateway 不承担领域逻辑；远程认证与多设备协作尚未形成完整能力 |
| 会话与上下文持久化 | SessionStore 保存会话元数据与展示历史；Blackboard 保存模型消息与上下文；文件保存资源和插件状态 | 展示历史、模型上下文和长期记忆是不同的数据与验收目标 |
| 历史与运行中纠偏 | 保存完整 Run 消息；保留工具调用与结果关系；运行中 Steer；取消时提交安全历史前缀 | 即时 Redirect 及更完整的中断、副作用语义仍待建设 |
| 工具与运行保护 | 基础 read/write/insert/bash；超时和输出预算；批次结果预算；长结果外置；Bash 进程清理；模型 Step 上限 | 同步线程工具不能保证被强制终止；执行预算不等于权限审批 |
| 基础 Compact | Blackboard 根据历史压力进行跨轮上下文压缩 | 尚未覆盖每次实际模型请求和整个 Active Run 的完整工作集治理 |
| Memory | 自动召回；显式读取、写入、纠正、停止引用、恢复引用、删除、历史查询；区分全局与 Workspace | 依赖自建 Mem0；自动召回有界并可降级；维护由主 Agent 调用工具决定 |
| Knowledge | 按需查询、列举、读取、上传与重编译 | 依赖自建 OpenKB；不向主 Agent 提供删除工具，也不接入第二套多轮聊天 Session |
| Skill | 发现、搜索、生产、演化和后台 Job 查询；状态持久化与终态通知 | 不等于已经具备完整自主成长流程；大目录和真实模型体验仍需验证 |
| MCP | 按需连接外部服务；固定的 list/search/execute 工具入口 | 外部工具接入不等于持续环境观察或自动触发任务 |
| TUI | 文本交互、Markdown 流式展示、thinking、工具预览、输入队列、取消、Steer、会话恢复与切换 | 未提交的本地队列不跨 TUI 进程持久化；图片剪贴板首期仅支持 macOS |
| 工程基础 | 安装、启动、停止、状态查询和测试脚本；各 App 依赖环境；Mem0/OpenKB 容器化及本地数据目录 | 本地自动化命令已有，仓库级 CI/CD 尚待建设 |

### 3.1 不能直接等同的能力

- 会话恢复已经实现，但崩溃后自动续跑原任务尚未形成完整机制；无法继续运行的旧任务会收束为中断状态。
- 记忆接口与自动召回已经实现，但长期理解质量、错误纠正效果和记忆时效性仍需真实使用验证。
- Mem0 的写入抽取和维护能力，不等于 Icarus 已有独立的后台经历整理与认知更新流程。
- Hook、日志和 Trace 已有，但它们不等于业务层的环境感知；Hook 不应承担主动行为的决策与控制。
- 任务内工具执行已有，但会话外主动触发、授权和副作用恢复仍需单独设计。

## 4. Mem0 与 OpenKB 前端现状

这两个前端属于各自服务的 Web 界面，使用各自的服务接口；它们不是 TUI，也不是已经完成的统一 Icarus WebUI。

| 前端 | 当前基础 | 新改造的状态 |
| --- | --- | --- |
| Mem0 Dashboard | React、Next.js、TypeScript、Tailwind CSS；已有登录、记忆、实体、配置、请求记录等页面源码 | Icarus 面向用户的风格、导航、布局、核心流程与验收范围待对齐 |
| OpenKB Web | React、Vite、TypeScript、Tailwind CSS；已有知识库列表、详情、设置、聊天等页面；已有 Icarus 构建适配与安全修补 | 资料管理、处理状态、内容呈现和统一视觉的改造范围待对齐 |
| 统一产品入口 | 当前两个服务页面与 TUI 分开存在 | 是否保留独立入口、仅统一风格，或建设统一 Icarus 管理界面，尚待决定 |

页面源码存在不代表本轮已验收每个页面；上游功能也不全部属于 Icarus 当前接入或计划交付的范围。

前端改造前需要确认：

- 主要使用者与核心任务：优先解决记忆查看和纠正，还是资料管理，或其他场景。
- 本期包含哪些页面、保留或隐藏哪些上游功能。
- 两个服务是否保持独立部署和入口。
- 仅修改视觉与交互，还是允许增加服务接口。
- 真实数据、空状态、加载、失败、权限和操作结果的验收标准。

| 方向 | 已有基础 | 未完成部分 |

| 长期质量评测 | 功能测试、集成测试、部分回放与 smoke 脚本 | 系统性的 30～50 轮质量评测、目标与事实保持、记忆纠正效果、成本与延迟基线 |
| CI | Makefile 与各应用测试脚本 | 当前未发现仓库根目录 GitHub Actions 工作流或所检查的其他常见 CI 配置；自动检查范围、触发规则和门禁待建立 |

外部托管平台是否配置额外流水线，不在本次仓库核对范围内。

## 6. 尚未形成完整实现的产品能力

| 能力 | 当前状态与缺口 |
| --- | --- |
| Session 外持续感知 | 运行时、插件和任务基础已有；Icarus 在没有用户输入或活动会话时持续接收业务环境变化的完整机制待建设 |
| 主动反应与行动 | 当前任务可接收运行中信息；独立判断忽略、记录、提醒或行动，以及去重和打扰控制的机制待建设 |
| 后台认知与记忆整理 | 显式维护工具和后端抽取能力已有；Icarus 独立整理经历、处理冲突和过期认识的流程待建设 |
| 统一 Icarus WebUI | 有方向性待办，尚未形成应用；不能与 Mem0/OpenKB 自带 Web 页面混同 |
| 桌面 GUI 与产品 Backend | 有方向性待办，新增职责和范围仍需确认；不应重复实现已有 AgentRuntime 与 SessionStore |
| 远程与多设备体验 | 目前主要面向本机；认证、访问控制和多设备协作尚未形成完整能力 |

服务自身的文件 watcher、后台任务或内部日志，不等于 Icarus 已经完成跨能力的主动感知链路。
搭档提出的应用级观察与主动操作属于新方向，尚不能据此认定具体架构方案和改动范围已经确定。

### 7.2 已发现的文档不同步

- `docs/TODO.md` 仍称具体功能设计统一放在根 `spec/`，与当前按应用、按功能组织的规则不一致。
- 部分旧插件事件流描述仍写着 Memory 尚未接入；当前实现已接入。
- Agent Core TODO 的历史问题背景仍保留“没有统一工具结果预算”等旧描述；后续勾选项及代码已实现结果保护。
- Steer 已有实现，但更大范围的中断语义待办中仍有未勾选的相关描述，不能据此认定 Steer 完全未做。

因此本文按具体能力核对，不按 TODO 勾选数量计算完成率。文档与实现冲突时，以当前代码和测试为事实依据。
