## 保留的基础能力

签名上报通过connector→handler→service直接收存并返回204。固定接收顺序前缀形成不可变批次，有界ready队列在后台执行同scope最早未结束批次，事务保证批次成员全有或全无。入站消息队列不再参与调用链。

图仍显式定义节点、条件边和必需数据依赖。普通图无环，顺序执行，保留分支汇合、局部失败阻断、有界重复、总预算、超时和取消传播。

## 当前变化

- 图包分node/edge/graph/compiler/state/runner，声明显式编译后执行；边有独立collect/状态/产物，执行器不导入QQ业务决定。
- evidence包获取并组装聊天、真实工作状态与近期交付事实；不再使用service/qq_materials.py。
- QQ图为human → decision_evidence边（conversation/work/activity/facts）→ code → 可选model → intervene → silent或relation/action → end。
- 不再用“无活动任务=新话题”或“模型判新话题=另起提交”的路由；排队与执行中区分，需要回应但暂不合适时waiting。
- 普通群聊和私聊均默认等待最后一条人类消息后的6秒安静窗口；私聊不再立即关批，群聊@/称呼/人类积压仍可提前判断。另保留普通群聊退避与近期启动退让，self-only不唤醒模型。
- 追加目标消失或明确拒绝不自动转submit，而是等待重新判断。发送未知仍阻塞且不自动重发。
- schema v3保存等待、明确时间、读取水位、强信号、发送尝试及逐轮安全轨迹；旧试验库拒绝启动，旧迁移工具已移除。

## 验证范围

当前图、证据、退避与等待流程已通过临时配置/数据库/假Gateway和Jev的自动测试，本轮未修改实际用户库、未重启服务、未做真实外部冒烟。记忆/知识/人物接入、styling、并行节点、跨客户端原子占位仍未实现。
