## 范围与规则承接

完整逐工具、逐规则的最终文案、覆盖结论和验收场景见 [Guidance → description 逐条承接表](plan-rule-mapping.md)。下面只保留所有者概览，不能代替逐条核对。

本次采用参考稿的职责划分，不直接替换为其英文草稿，也不放宽现有预算。人格正文与 boundaries/anti-goals 保留，JEV invariants 继续来自原有正文；因此无需引入第二份边界配置。演化指导拆成独立、按能力条件贡献的段。

| 规则 | 修复后的所有者 |
|---|---|
| 事实、执行结果、授权、澄清、工作区规范、人格权限边界 | base |
| 常驻/延迟工具、每 Run 加载、加载不等于业务授权 | base；完整定义与裁剪恢复细则在 tool_search description |

| 写入前读取、覆盖/插入语义 | 各工具 description；命令选择和退出结果核实留 builtin guidance/base |
| Memory 原话抽取、scope、correct 前 read、停止/删除语义 | 对应工具及字段 description |

跨工具协作、调用场景和必要的局部安全提醒仍可留在轻量 guidance，不要求机械零重复；字段 schema 不替代执行层的硬校验。Skill 的生成/演化开关控制指导与执行许可，工具仍可注册；不能用“已注册”推断“当前允许执行”。

## 运行时策略边界

保留 workspace 的现有可选来源和超限省略策略；本次补充原因日志，不隐式改为启动阻断，不递归加载全仓规范。guidance 仍按会话静态贡献，不改成随工具加载，也不改 Plugin/Event/Agent 层边界。用户可见降级状态需要明确的上层协议设计，本次不新增协议或框架抽象。

## 验证解释

离线测试验证实际 schema、加载/分页状态、贡献位置、失败分支与预算。文案的规则存在性断言只防止规则被误删，不代表真实模型已经遵守它。普通聊天不过度查询、JEV 拒绝越界观察等行为仍需真实模型评估；本次不调用收费模型或真实外部存储。
