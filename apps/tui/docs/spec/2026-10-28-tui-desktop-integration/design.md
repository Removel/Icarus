## 2. 意图与成功标准

用户当前在 WSL 中不能可靠粘贴图片、复制文字。目标是在 macOS、Windows、Linux 桌面本机和 WSL 中，提供一致的操作语义：图片粘贴、系统文本复制、系统文本粘贴、输入框文本剪切、点击网址打开浏览器。

“一致”指结果可预测，不要求终端截获规则、桌面依赖或系统调用完全一致。复制结果必须能粘贴到其他桌面应用，不能只更新 TUI 内部字符串；WSL 操作的是 Windows 宿主剪贴板和默认浏览器。

### 2.1 用户已确认的范围

1. 支持 macOS、Windows、Linux 桌面本机以及 WSL；暂不考虑 SSH。
2. 输入框、聊天内容均可选中文字并复制；聊天区允许跨多条消息连续选择。
3. `Ctrl+C` 有有效选区时优先复制，无有效选区时保留现有中断逻辑。
4. 剪切仅针对输入框的选中文字；系统剪贴板写入成功后才能删除原文。
5. 图片来源包括系统截图、浏览器复制的图片、文件管理器复制的本地图片文件。
6. 单次粘贴仅处理一张图片，多图粘贴不在本次范围。
7. 点击网址，打开桌面浏览器并请求访问对应网址。

### 2.2 非目标与反目标

- 不支持 SSH/远程剪贴板桥接，不以 OSC 52 查询或写入作为本次成功保证。
- 不实现多图单次粘贴、文件拖放、普通文件附件、视频、目录粘贴、剪贴板历史或持续监控。
- 不自动下载“复制图片地址”得到的 URL，不把普通文本路径自动转成图片附件。
- 不重写 ReActAgent、Plugin Runtime、Gateway 或现有消息提交机制。
- 不另造终端输入协议，不保证被终端截获的按键能送到应用。
- 不提前删除剪切原文，不因复制失败继续取消任务或退出，不静默选择多个文件中的第一张。
- 不为方便选择而取消历史窗口化、无限挂载全部消息或维护第二份可编辑聊天记录。
- 不把 mock、Pilot 或 WSL 的测试结果当成 macOS、Windows、Linux 原生实机验收。

## 4. 交互契约

### 4.1 选区、焦点与 Ctrl+C

输入框选区与聊天选区只有一个当前操作拥有者。用户在另一区域建立新选区、开始编辑输入框或明确取消选择时，旧区域的有效选区应取消，不根据焦点盲目复制另一处残留选择。有效选区是实际非零长度范围；选中空白字符同样可复制，不使用 `strip()` 判断是否有选区。

`Ctrl+C` 的优先级：

1. 有输入框选区：取选中文字，发起系统复制并消费按键。
2. 否则有聊天区选区：取跨消息文本，发起系统复制并消费按键。
3. 否则沿用现有中断流程：有草稿清草稿、有可恢复待发消息则恢复、有活动任务则取消、空闲则退出；以 `domain/chat_state.py` 的实际决策为准，不新增双击退出语义。

复制期间即使选区随后消失或复制失败，此次按键也不能落入第 3 步。连续复制请求按顺序执行，避免较早请求迟到覆盖较新内容。成功后保留选区，允许重试或继续扩展；按 Escape 取消当前选择，不改变草稿或任务。

输入框沿用 TextArea 的鼠标与 Shift+方向键选择。聊天区复用 Screen 鼠标跨 Widget 选择；还须提供可发现的键盘选择模式：从当前阅读位置进入，使用方向键/翻页移动选择端点，Shift 扩展，Ctrl+C 复制，Escape 退出。进入模式的具体键或命令在实施时避开现有绑定确定并写入提示；不能以“只能用终端原生鼠标选择”交付。

### 4.2 聊天文本的复制内容

- 复制用户实际选中的可见文字，按消息与块的阅读顺序拼接；消息之间用空行分隔。
- 不包含角色装饰、按钮、导航栏、队列、运行状态、折叠控制标题等界面元素。
- 展开的 Thinking/工具文本属于可见内容，可选择复制；折叠隐藏正文不隐式展开，也不复制。
- Markdown 复制渲染后的文字，代码保留必要换行和缩进；不额外带 Markdown 标记、软换行或 CJK 辅助字符。
- 中文、emoji、宽字符、窄屏软换行必须按文字范围提取，不能靠屏幕截图或 cell 列数直接切字符串。
- 跨消息选择包含选区之间的正文，不越过选区擅自复制整条消息，不补入未显示的折叠内容。

### 4.3 文本与图片粘贴

输入框聚焦时，`Ctrl+V` 和现有右键入口发起应用粘贴；在框架确实收到 `super+v` 的终端中可提供同义绑定，但不把它作为 macOS 通用保证。

两类输入分别处理，不能相互重复：

- **应用粘贴动作**：读取系统剪贴板，识别文件引用、图片或文本，然后回填输入框。
- **终端文本 Paste 事件**：直接插入事件中的文字，不再读取系统剪贴板，不尝试把文字解码成图片。

粘贴只在输入框生效，不向聊天历史插入内容、不自动提交。文字在当前光标插入或替换当前选区，保留空白、Unicode 与多行；系统 CRLF 可规范成编辑器的 LF，不擅自 trim、去重或压缩空行。

系统剪贴板识别优先级由本文选定为：

1. 存在原生文件引用时先检查数量；多个文件整体拒绝，单个图片文件读取为图片，单个非图片文件提示不支持，不回退插入文件列表或路径。
2. 否则读取原生图片表示；同一图片的多个 MIME 表示不算多图，选择一种可支持的表示。
3. 无文件和图片时读取普通文本，包括 URL 和普通文本路径。
4. 空剪贴板、不支持类型与读取失败有不同反馈；不能用旧的应用内部缓存代替当前系统内容。

每次读取和写入有超时；同类重复粘贴不并发读取、不过度排队。异步期间保留已有草稿；成功回填到同一草稿的当前选区，用户切换会话、清空或恢复草稿后，旧结果丢弃并释放临时图片。若用户离开输入区域且期间有其他编辑操作，不强抢焦点，提示重新粘贴；具体 token 校验复用并扩展现有机制。

### 4.4 单张图片处理

- 截图、浏览器“复制图片”、文件管理器复制单个图片文件，最终进入同一 `DraftImage`/`[#imageN]` 草稿附件路径。
- 读取文件引用后将内容快照写到受控资源目录，不将任意源路径直接提交为 ResourceRef；用户之后移动或删除原文件不影响已加入的草稿。
- WSL 文件引用来自 Windows；正确处理盘符、UNC、空格和 Unicode，不能简单字符串替换成 `/mnt/c`。
- 原文件不被修改或删除。暂存失败不插 marker；草稿替换、取消、提交与退出沿用现有释放生命周期，不因工作线程取消造成孤儿文件。
- 本次默认支持有效 PNG/JPEG；剪贴板的常见 DIB/TIFF 表示需转换成支持的 PNG。文件按真实内容验证，不只信任扩展名；其他格式明确提示不支持，不默默读取为文字。最终转换工具可由实施者选择，但新增依赖必须在 `apps/tui` 声明。
- 每次只粘贴一张；不额外限制同一草稿先后粘贴多次形成多个附件。
- 本文暂定输入安全上限为单张编码数据 20 MiB、解码后 40 百万像素；超限明确拒绝，并覆盖转换后大小。该上限是设计默认值，不是已验证的下游最大承载能力；实施时若发现更严格的既有约束，应在开始编码前统一上限并更新本文。
- 复制文本中的 `[#imageN]` 只复制 marker 文字，不携带图片数据；本次不实现跨草稿复制附件。

### 4.5 安全文本剪切

仅在输入框存在非空范围且可编辑时响应 `Ctrl+X`；收到 `super+x` 时可作为别名。无选区不剪整行；聊天区不剪切。

1. 主线程捕获文字、选区起止、编辑版本与草稿身份。
2. 后台向 OS 写入捕获的文字；OS API/所选工具报告成功才产生成功结果。
3. 主线程检查草稿身份、文字版本与选区仍与快照一致，再通过 TextArea 编辑接口删除原范围，保留撤销能力。
4. 写入失败：文字与选区保留，提示可重试。
5. 写入成功但快照已过期：不删除任何文字，提示“已复制，输入已变化，未剪切”。

不以 OSC 52 发送成功或应用缓存变化判定 OS 写入成功；也不承诺写入后剪贴板不会被其他应用再次覆盖。重复剪切对同一快照至多执行一次，不允许用迟到回调重复删除。剪切图片 marker 仅改变文字引用，不删除用户源文件，也不新增将图片写入剪贴板的含义。

### 4.6 链接打开

- 支持用户消息、助手正文与展开的 Thinking/工具正文中的 HTTP/HTTPS 裸 URL，以及 Markdown 链接实际指向的 HTTP/HTTPS 地址。
- 单击打开；从链接处开始拖动选择、双击选择文字时不打开，不能把复制交互变成浏览器弹窗。
- 统一校验 URL，只允许结构有效的 `http`/`https` 网址，拒绝控制字符和其他 scheme；不把网址拼进 shell，不执行 Markdown 内嵌命令。
- 裸 URL 识别注意中文标点、括号及换行；代码块/代码片段不自动 linkify，避免改变代码选择行为。Markdown 中已明确声明的链接沿用其目标。
- 不在输入框单击时打开 URL，输入框仍是编辑器。
- 提供可发现的键盘“打开链接”动作，列出当前消息或当前阅读区域的目标 URL；先定位正文消息，再选链接，无须把每个链接加入全局 Tab 链。无链接时明确反馈，不默默打开会话里的最后一个 URL。
- 本机委托本机默认浏览器；WSL 委托 Windows 默认浏览器。已配置非默认浏览器的用户仍以系统默认关联为准，本次不新增浏览器配置。
- 打开是用户明确点击或选择的动作，不在渲染或流式更新时自动打开。失败提示可重试；成功只表示 OS 接受请求，不宣称网页加载成功。

## 5. 跨消息选区与流式、窗口化协调

这是本项目首要技术风险，应先做隔离、可丢弃的验证，再选定最小必要实现。验证结果记录到本功能目录，不能把实验代码直接当生产交付。

### 5.1 必须维持的语义

- 跨多条消息可连续选择，拖到视口边缘可滚动扩展；不能只支持可见一屏或一条消息。
- 有聊天选择或正在拖选时，暂停自动追尾和会卸载所选内容的自动窗口回收；网络接收、业务状态应用继续运行。
- 选择已存在的文字时，后续流式尾部追加不自动纳入选区，不改变用户选择的原文。
- 自动 Markdown 重解析或历史加载不得悄悄使旧选区指向另一段文字；窗口切换、节点替换需保持语义端点，不能用失效 Widget 引用继续提取。
- 选择中加载更早历史需要保留选择起点。不得简单禁用翻页或无限扩大 DOM 窗口来规避要求。
- 用户主动切换会话、跳转另一轮次或离开聊天页时明确取消当前聊天选择，防止旧会话选区作用到新会话；普通滚动扩选不是主动取消。

### 5.2 实现选择门槛

优先复用 Screen 选区、Widget 文本提取和现有稳定消息投影。先验证中文/emoji、跨消息、代码块、流式末块替换、向上跨 24 轮边界、链接拖选、键盘选择。

若原生选区在窗口切换/流式替换后无法维持目标语义，仅增加所需的稳定端点：按消息/显示单元身份和文字偏移定位，必要时保留被选文字片段快照，利用现有 ConversationProjection 提取范围；原生 Screen 选区负责可见区域交互与高亮。不要另建全文消息 Store。

逻辑选择状态属于 ConversationView 及其局部组件，不进入业务 ChatState。需要跨窗口高亮时，将语义端点重新映射到当前挂载文本。先明确显示文字与 Markdown 源码偏移的映射再编码，不能直接以源码 substring 替代渲染选区。

若实验表明需要显著重做渲染或无法在既有窗口化上达标，应暂停提交生产实现，报告实测限制和设计调整；不能静默把范围降为当前窗口。

## 6. 平台实现方向

平台选择收在 `platform/`，上层不判断操作系统、X11/Wayland 或 WSL。

| 环境 | 剪贴板实现方向 | URL 打开方向 |
| --- | --- | --- |
| macOS | 保留 AppKit 图片读取，补系统文本读写及文件引用；纯文本可使用 `pbpaste`/`pbcopy`，格式判断与文件引用用 Pasteboard | 系统默认 URL 打开入口 |
| Windows | Win32 Unicode 文本读写、PNG/DIB 图片与文件列表；忙碌时有限重试，正确处理句柄与内存所有权 | 系统默认 URL 关联 |
| Linux Wayland | 有有效桌面环境且工具可用时使用 `wl-paste`/`wl-copy`，按 MIME 判别文本、图片与文件引用 | 桌面默认 URL launcher |
| Linux X11 | `xclip` 提供文本、图片、TARGETS/文件引用；不引入仅支持文本的后端作为图片成功路径 | 桌面默认 URL launcher |
| WSL | 先识别 WSL 并优先访问 Windows 宿主；固定 Windows 侧辅助脚本读取文本、图片、文件引用及写文本，不依赖 WSLg 的另一份剪贴板恰好同步 | 经 Windows 侧系统入口请求默认浏览器 |

选择依据不只检查二进制是否存在，还检查 DISPLAY/WAYLAND_DISPLAY、工具退出状态与运行能力。Wayland/X11 按当前可用桌面路径选择，不把 `wl-paste` 已安装等同于可用；桌面类型改变后允许重新探测。WSL 互操作不可用时明确报错，不悄悄读 Linux 剪贴板并宣称宿主成功。

Windows 侧辅助代码是仓库自有固定脚本，不将图片文件名、文字、URL 插入脚本字符串；通过标准输入/参数数据通道传递并正确编码。避免 `cmd /c start <拼接URL>`，临时文件和脚本执行均遵守安全路径规则。图片返回采用有界字节或结构化编码，验证类型与大小。WSL 不能仅靠 `clip.exe` 完成图片读取。

Linux 依赖不自动安装，WSL 不自动启用互操作或修改系统策略；缺少能力时提供具体下一步操作。文本复制/剪切缺少系统路径时报失败，不用内部缓存冒充系统写入。保留终端原生文本 Paste 能力。

## 7. 调用链与职责边界

### 7.1 共通模式

Widget 发明确意图 Message，ChatScreen 判断选区、当前区域与交互状态，App 管理长时间 I/O Worker，普通 service 调用 platform 并返回捕获结果；结果在主消息路径串行采用，最后由拥有 DOM 的 Screen/Widget 更新视图。

- `platform/clipboard.py`：内容类型识别、系统读取、文本写入；保留并按需扩展现有 ClipboardImage 公共值类型。
- 拟新增 `platform/opener.py`：HTTP/HTTPS 校验后的系统 URL 打开；同样无 Textual 依赖。
- `services/attachments.py`：复用图片受控快照、资源身份、暂存与释放；普通文本读写与 URL 打开可由轻量桌面 I/O service 承接，具体拆文件由调用者复杂度决定，不建立 Backend/Provider/Manager 层级。
- `widgets/chat/composer.py`：输入选区、编辑版本、粘贴插入、剪切删除与撤销，不调用系统 API。
- `widgets/chat/conversation.py` 及局部文字组件：聊天选区、稳定位置、范围提取、链接点击/拖选仲裁，不直接访问 Gateway。
- `screens/chat/screen.py`：选区拥有者、Ctrl+C 优先级、键盘入口、请求路由与近端反馈。
- `app.py`：依赖装配、后台 Worker 生命周期、结果串行投递和关闭排空，不新增正文识别或编辑实现。

### 7.2 操作路径

| 操作 | 调用与结果 |
| --- | --- |
| 图片粘贴 | Composer 粘贴请求 → Screen → App Worker → 系统读取/AttachmentsService 暂存 → 身份校验 → Composer 插入 marker |
| 文本粘贴 | 同一系统读取路径返回文本 → 身份校验 → Composer 替换当前选区；终端 Paste 事件则直接走 Composer |
| 文本复制 | Screen 获取当前选区文字快照 → App Worker → service/platform 写系统剪贴板 → 反馈结果，保留选区 |
| 文本剪切 | Composer 捕获编辑快照 → 系统写入 → 成功且快照未过期 → Composer 删除原范围，否则保留原文 |
| 打开 URL | 正文链接点击或键盘选择 → Screen 请求 → service/platform 校验并打开 → 结果反馈 |

复制、剪切与打开链接是桌面交互，不新增到 ChatSession 的提交/取消业务决策中。现有图片粘贴已通过 ChatSession 的 `clipboard` Operation，首阶段可保留适配；实施计划须选择是否将这条已有桌面 I/O 一并归拢，并确保没有两套竞争的粘贴入口。不为统一外形扩散通用 Operation 框架。

系统调用不在 Textual 消息处理函数同步阻塞；后台线程不能直接编辑 Widget。请求绑定相应草稿/会话/视图身份；复制写入已捕获文字可以完成，迟到的删除、插入、焦点变更必须被拦截。关闭时排空真实系统读取并释放临时资源，不能只取消 await 后立即删目录。日志和异常不输出剪贴板正文或图片数据。

## 8. 反馈与可发现性

复用现有 notify/局部状态反馈，区分：正在读取、已复制、已剪切、剪贴板为空、类型不支持、多文件不支持、超限、工具缺失、超时、系统拒绝访问、浏览器请求失败、结果过期。

复制和剪切成功给简短反馈，不展示敏感正文；失败保留选区和输入并说明下一步。关键错误不通过裸异常或日志替代用户反馈。帮助/欢迎提示/命令入口同步说明 Ctrl+C 规则、剪切仅输入框、应用图片粘贴与终端文本粘贴的区别。

终端可能截获 Cmd+V、Ctrl+Shift+V、右键；只有交给 TUI 的动作才能触发应用图片读取。验收记录具体终端和设置，并提供实际可用的应用粘贴入口，不承诺任意终端的原生粘贴键都会传图片。

## 9. 实施前验证与验收

### 9.1 首个技术验证

隔离验证 Textual 8.2.8 的跨消息选择与历史窗口行为，以及链接点击/拖选冲突。可丢弃验证不作为生产功能完成依据；记录可复现步骤、通过项、失败项，再决定原生 API 足够还是需稳定端点适配。此步骤先于正式选区实现。

### 9.2 自动化测试契约

- 平台：环境探测、WSL 优先级、类型与多文件识别、Unicode/换行、图片转换与损坏/超限、超时、缺工具、Windows 句柄释放、子进程数据通道及 URL scheme 校验。
- 服务：受控资源快照、源文件保留、失败清理、线程取消后排空、请求排序、过期结果、系统写成功/失败可区分。
- 输入框：选区复制、无选区剪切不操作、成功后删除与撤销、写入失败保留原文、期间修改/提交/清空/切会话不误删、普通 Paste 不重复读取、图片 marker 与普通文本路径。
- 聊天：跨用户/助手消息、跨 Markdown 块、中文/emoji/代码、展开与折叠内容、排除界面文字、流式尾部不扩选、跨历史窗口滚动扩选、键盘等价操作。
- Ctrl+C：输入/聊天有选区时绝不中断，空白选区可复制；无选区逐项回归原草稿/待发/活动任务/空闲行为。
- URL：Markdown 与裸网址、标点边界、非法 scheme、参数注入防护、单击打开、拖选/双击不打开、键盘入口、WSL 宿主路由、失败反馈。
- 架构：platform/service 不依赖 Textual，Widget 不调用 Gateway 或系统 I/O，App 不承担选区正文逻辑。

按最小受影响测试 → `make test-tui` → compile → `git diff --check` 顺序验证。不恢复已删除的 SVG 基线；宽/窄/短屏通过 Pilot 语义测试和临时真实 App 截图检查。

### 9.3 实机验收矩阵

macOS、Windows、Linux Wayland、Linux X11、WSL 分别记录系统、终端、依赖和实测结果：

1. 输入框选区、跨至少三条聊天消息的选区复制到外部编辑器，中文、emoji、换行正确。
2. 输入框剪切成功可外贴、可撤销；模拟写入失败原文保留；后台迟到不能误删。
3. 从外部应用粘贴多行文本到选区/光标处，内容只插入一次且不发送。
4. 截图、浏览器复制图片、复制单个 PNG/JPEG 文件分别形成附件；移动源文件后附件仍有效；多文件明确拒绝。
5. 流式输出期间选择、跨历史窗口扩选，选区与阅读位置保持稳定。
6. Markdown/裸 URL 单击打开对应默认浏览器；拖选不打开；WSL 必须进入 Windows 浏览器。
7. 有选区 Ctrl+C 不取消/退出，无选区现有中断行为不变；退出恢复终端并清理暂存资源。

没有目标系统实机条件的项标为“未验证”，不可写为完整跨平台完成；WSL 上存在命令不代表互操作已通过实测。

## 10. 本文选定默认值与留给实施者的决定

以下是基于讨论由设计者补充的默认值，不冒充用户逐项指定：

- 多文件整体拒绝；文件引用优先于图片表示，图片优先于文本；PNG/JPEG 作为基础文件格式，DIB/TIFF 转 PNG。
- 默认单张 20 MiB 编码数据、40 百万解码像素，实施前与既有下游约束核对。
- 复制渲染正文而非 Markdown 源码，消息间空行，不带角色装饰，展开的 Thinking/工具正文可复制。
- 剪切成功后仍检查文字版本和选区；过期只复制不删除；无选区不剪整行。
- 复制保留选择、Escape 取消；用户主动会话/轮次跳转取消选择，普通滚动扩选不取消。
- 只打开 HTTP/HTTPS，代码不自动 linkify，WSL 走宿主，提供键盘链接列表入口。
- Linux 用桌面工具、WSL 用固定宿主辅助脚本，不自动安装/修改系统，不用内部缓存冒充系统成功。

实施者可以在不改变上述契约的前提下决定：具体消息类和 service 文件名、剪贴板结果的最小类型扩展、平台内部拆分、受控图像转换实现、键盘模式入口键位、超时与有限重试细节。跨窗口选区最终机制由首个验证决定；若要改变范围、格式边界、默认值或引入重大依赖，先更新本文并说明差异，不在代码里暗自降低体验。
