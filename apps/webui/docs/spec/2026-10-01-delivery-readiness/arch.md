# WebUI 交付架构

2026-10-01，依据当前 `apps/shell`、`packages`、`server` 及对应测试整理。

Shell 使用 hash 路由组合记忆、知识和对话 workspace 包。记忆和知识模块保持挂载以保留筛选、阅读与编辑状态；对话包首次进入时懒加载。共用 UI 包包含视觉组件、导航、未保存草稿保护和 Gateway 传输客户端；记忆配置读取与对话复用该客户端。各业务模块拥有自己的服务适配，不互相导入业务实现。

记忆通过 `mem0.ts` 调用同源 `/api/mem0`，`useMemories` 管理可取消的列表、详情、历史读取。页面使用服务 ID，写入由服务确认后回读或刷新；服务错误保留编辑草稿，批量操作逐条统计结果。新增表单独立为 `MemoryCreate`，通过 Gateway `memory.get_context` 获取配置中的身份，工作区范围复用服务端 `SessionIdentity`，不在浏览器重算路径散列；原文创建使用 `infer: false`，更新保留 metadata，暂停写过去的 expiration_date，恢复写 null。记忆列表调用 Mem0 `/memories/page`，服务先对最多 1000 条的查询快照筛选、排序，再返回每页 12 条及总数、筛选选项；超出查询上限时明确提示。前端翻页和切换筛选会取消旧请求，批量选择只作用于当前页。卡片正文最多两行，状态、分类、用户和截断的范围标签在紧凑属性行展示；正文位于属性之前。详情保留可读的记录来源；Agent 来源会话、执行、工作区与操作标识收进默认折叠的「来源信息」，按需展开并复制，缺少这些标识时不显示此区块。重新打开详情恢复折叠，元数据继续完整保存，作用范围仍使用顶层 run_id。历史按每页 10 条展示，读取仍为全量。Mem0 `changes` 提供分类和有效期前后值，旧数据保持通用更新标签；正文使用共同前后缀裁剪得到变化区段，全文按需展开。

知识包的 `openkb.ts` 对接 `/api/v1`。列表与图谱分别请求，图谱失败不阻断资料阅读；正文按需读取。知识页保存、资料导入、重编译、移除和检查继续调用 OpenKB。知识库的新建、刷新以独立按钮展示，已移除示例模式及示例数据。Markdown 渲染、React Flow 布局均由前端完成。`KnowledgeQuality` 从 OpenKB `list.reports` 读取服务端档案，每页展示 10 份；通过 page 接口读取全文并在弹窗中展示或导出，通过 report/delete 确认删除。检查完成重新读取目录；浏览器不另存报告副本。报告是检查时的快照，不随库内容变化更新。

共用包的 `Gateway` 通过 `/rpc` WebSocket 管理 JSON-RPC 请求 ID、超时和关闭时的未完成请求；`useChatSession` 调用会话创建、列表、删除、订阅、历史、提交和取消。工作区连接独立于当前会话，切换时只更新订阅与历史；新建传 `load_runtime: false`，首次提交再初始化 Agent。先订阅，再按游标读取历史，同时缓存实时更新；历史与通知按 sequence 去重，完整消息替代同一步的 delta，迟到 delta 不覆盖完整消息。`updates.ts` 只解释公共 RuntimeUpdate，不依赖模型供应商协议。未知事件忽略。断线重新连接并读取历史，不自动重发输入；用户显式重试复用 submission_id。`ChatApp` 负责会话侧栏与输入布局，会话切换保留列表，新建成功立即插入列表；选中的条目移出可视区时只滚动到最近可见位置，发送时立即用首条消息更新临时标题；明确拒绝时回退。提交后立即显示本地用户消息并进入执行状态，接收确认在后台进行；公共 user.message 替换本地消息，避免重复气泡。等待确认期间仍可编辑下一条草稿，失败恢复原输入并保留新草稿；提前停止在取得任务编号后立即发送取消请求。`ChatTranscript` 使用 react-markdown 与 remark-gfm 渲染用户及助手消息，不执行原始 HTML，链接协议由默认 URL 校验限制；它同时负责跟随滚动；读取历史时停止自动跟随，并提供回到最新消息按钮和带搜索的消息定位控件。思考与工具按 task ID 合并为默认折叠的执行区，内部明细按需展开。输入框最少一行，Enter 发送，Shift + Enter 换行；输入法组合输入期间禁止快捷发送。删除经确认调用 `session.delete`，服务成功后更新列表并切换到剩余会话。记忆、知识和对话读取使用共用的居中加载动画，刷新期间仍保留上次数据。

`server/index.mjs` 使用 Node 原生 HTTP/HTTPS 实现静态资源、HTTP 流式转发和 WebSocket 隧道。它把 Mem0 路由前缀去掉，保留 OpenKB `/api/v1` 与 Gateway `/rpc`。后端令牌只从进程环境读取，在服务端加入；客户端入口凭据与 Cookie 被移除。非回环监听必须启用 Basic 认证，写入与 WebSocket 校验配置的 Origin。静态路径解析后验证真实路径属于构建目录，防止越界或符号链接逃逸。`/health` 是进程存活探针，`check-services.mjs` 另行检查真实后端读取接口。

测试与源码层次对应：`test/packages/memory_app` 使用有状态 HTTP 响应验证服务契约及刷新；`test/packages/chat_app` 使用可控 WebSocket 验证公共协议、流式合并、分页、取消、错误与重连；`test/server` 启动真实 Node 入口和隔离 HTTP/WebSocket 对端验证代理与访问控制。这些测试不声称验证真实模型或真实后端存储。生产 Dockerfile 构建静态产物后仅复制产物与 Node 入口，CI 运行应用回归、lint、format、类型、构建和 diff 检查。

知识库子导航位于知识库入口下方，在所有模块始终展开，不提供分组折叠操作。导航采用扁平树结构：知识库父级为普通文字行，没有背景、描边或强调色；子级字号 13 px、缩进 16 px，展开侧栏不使用竖向连接线，仅当前页面使用浅底色与品牌文字/图标色。主行 40 px、组间隔 6 px、子行 32 px，所有菜单图标统一 1.5 px 描边。收起侧栏与窄屏图标栏保留 18 px 一级图标、14 px 二级图标，二级组左边距 8 px、左内边距 5 px，并以组内浅色竖线区分层级；竖线与父级留有间距。手机显示四列子导航，不使用竖线。通过公共导航进入知识库，保留知识库选择并继续遵循草稿保护；切到其他模块时知识子项均不高亮。知识库选择与名称搜索框限制宽度。质量检查操作位于选择行下方，报告标题、空状态与报告列表独立展示；离开质量页时关闭报告弹窗的可见性。

Shell 的 theme.ts 管理浅色、深色、跟随系统三种模式，默认跟随系统；localStorage 保存用户选择，matchMedia 监听系统变化，storage 事件同步同源标签页。启动时先应用主题再渲染 React；主题映射到 html data-theme 和 Semi body theme-mode。UI 包以中性灰、粉色品牌及局部成功/失败色统一覆盖 Semi 语义变量，关系画布使用相同变量。顶栏的主题菜单适用于桌面与窄屏；设计规范提供两套色板和离线切换示例。

会话列表不展示逐条图标，仅保留单行标题，截断的长标题在悬浮或键盘聚焦时滚动；Tooltip 提供全文、相对时间和绝对时间，使用主题表面色和正文色保证对比度。首条成功提交或恢复无标题会话时异步调用 session.generate_title，不占用提交的 busy 状态；成功后更新列表和页头，失败沿用 first_user_input。生成的标题保存在 Agent 服务端，刷新从 session.list 恢复。记忆卡片更新时间右置。报告导出独立使用 exporting 状态，不改变质量检查 busy，不刷新列表或关闭阅读弹窗；下载使用隐藏链接，延后回收 Blob URL。

`ChatContent` 在展示层按动画帧渐进呈现实时回复与思考文本，突发片段动态加速追赶；完整消息仍通过原有事件合并校正，不改变原始事件或历史。历史加载与减少动效模式直接显示全文。帧更新沿用消息区的跟随状态，阅读旧消息时不移动滚动位置。标题与新执行区使用短暂淡入；发送后、首个回复内容到达前展示“正在思考中”，思考片段、工具事件或正文到达后替换该提示，失败与任务结束时移除。

`ChatProcess` 独立管理执行明细的滚动跟随。窗口最高 194 px，可容纳五条折叠明细；展开正文仍在窗口内阅读。新条目默认滚到最新，用户向上滚动后保留位置，滚回底部恢复跟随，不提供额外按钮。思考块关闭浏览器默认 details 标记，仅保留一个自定义三角。`ThinkingWave` 的五根波浪条用于首个响应等待及进行中的执行区，直到 task.finished 移除；非活动页面暂停，减少动效模式静止。消息区与过程区都在展示帧写入滚动位置前检查用户是否已向上移动，避免晚到的 scroll 事件造成回跳。

`useChatSession` 保存当前页面、当前会话的待发送队列，不在服务器或浏览器存储中另建消息队列。空闲时 Enter 直接提交，执行中或等待提交确认时 Enter 排队；task.finished 后逐条调用 session.submit。排队消息可删除或移回草稿，编辑时暂停队列；停止当前任务也暂停队列，明确发送失败或未知结果恢复原消息、保留新草稿并暂停。历史同步未完成或失败时不自动发送。引导按钮调用已有 session.steer，复用当前 task ID；接收成功后显示“引导待应用”，user.correction 去重替换本地消息并显示“引导已应用”，任务结束仍未收到应用事件则标记“引导未应用”。未知结果重试保持原 RPC 方法、task ID 和 submission_id，已结束或正在取消的引导恢复草稿，避免隐式变为新任务。

草稿与待发送队列共同参与导航和刷新保护；离开与删除弹窗宽 360 px，只展示一句确认问题与两个操作，危险操作使用强调色；不展示重复说明，空正文不占空间。确认期间不自动派发队列；放弃同时清空草稿与队列，再执行待定导航，防止保持挂载的对话模块重复拦截。删除失败时在弹窗中保留错误提示以便重试。会话标题左右留白 6 px，删除按钮仅悬浮时预留空间；行高至少 36 px、行间留 3 px。列表滚动条靠近侧栏右边缘，轨道透明、滑块低对比，悬浮时略增强。长标题滚动周期为 max(2.8, distance / 70 + 1.5) 秒，保持首尾停顿与减少动效保护。全文提示使用紧凑行高与间距，关闭提示的出入动画，避免快速重复悬浮被组件动画状态吞掉。输入框初始显式使用一行，与输入后及清空后的高度一致，多行输入自动增高至五行；输入框和底部发送、引导、停止操作共用一个边框容器，不展示快捷键说明。

质量检查成功后使用短暂的「检查完成」提示，不在报告列表上方保留成功说明；跳过检查的原因仍显示，失败继续通过错误区域反馈。

`EvidenceCanvas` 保留完整节点与关系数据，布局仍依据完整拓扑计算。默认显示从真实关系构造的生成森林，每个连通分量保留连通路径，减少密集双向引用与来源线的交叉；悬浮或键盘聚焦节点时显示它的全部直接关联，连线保持方向箭头与关系类型。全部连线切换恢复所有真实边，不重排节点、不重置视角。图例与节点使用独立主题变量 graph-source、graph-summary、graph-concept、graph-entity，分别为绿、紫、玫瑰、橙；来源与引用分别保留绿和玫瑰色。浅色与深色提供各自色值，选中线继续保持类型色；全局仍采用粉灰主题，移除旧的偏蓝阴影。
