# 人物工作台架构

更新日期：2026-10-28。本文依据当前 WebUI、rela REST、Agent relationship 工具源码及对应测试整理。实现与验证范围见 [交付记录](plan-delivery-report.md)。

## 组件边界

Shell 在 `apps/shell/src/App.tsx` 中识别 `#/people`，懒加载 `@icarus/relationship-app`，通过现有管理页容器承载，并提供顶部分类与操作插槽。Shell 保留各模块路径；ChatApp 保持挂载，管理页浏览不会创建会话。左下角 DswSidebar 账户菜单统一提供知识库、记忆和人物入口。

人物业务归 `packages/relationship-app`，只依赖 React、公共 UI 和 lucide 图标。它不导入记忆/知识库实现，不连接数据库，也不依赖 Agent Runtime。当前人物数据不随对话工作区隔离。

| 文件 | 职责 |
| --- | --- |
| `RelationshipApp.tsx` | 列表查询、分类、游标、详情路由、返回位置和焦点 |
| `PersonCard.tsx`、`relationship.css` | 身份线索、缩写 ID、响应式卡片与阅读布局 |
| `PersonDetail.tsx` | 基础信息及按需读取的档案、关系、圈子、别名/身份核对 |
| `CircleDetail.tsx` | 圈子定位、阅读弹窗、成员分页与操作 |
| `PersonForms.tsx`、`RelationForm.tsx`、`CircleForms.tsx` | 独立 REST 写表单 |
| `PersonPicker.tsx` | 服务端姓名/别名搜索、候选消歧与分页 |
| `WriteDialog.tsx` | 单次提交、忙碌保护、草稿保护及未知结果核对 |
| `rela.ts`、`useRead.ts`、`ReadState.tsx` | 请求、错误语义、取消/旧响应隔离、重试与分页控件 |
| `types.ts` | 当前使用的 REST 字段及展示辅助函数 |

## 请求与代理

浏览器只请求同源 `/api/rela/v1/...`。Vite 与生产 Node 入口剥离 `/api/rela`，转发至固定配置 `ICARUS_RELATIONSHIP_ENDPOINT`，默认 `http://127.0.0.1:8767`。`RELA_MEM_API_TOKEN` 由服务端附加 Bearer 头；清除浏览器 Authorization、Cookie 和客户端服务凭据。开发入口从仓库根环境文件读取 Token，生产进程使用显式环境配置，原生启动器仅导入白名单。

生产 WebSocket 升级按 `/rpc` 前缀选择 Gateway 目标，不依赖路由数组下标。代理回归为 Gateway 配置独立端口，普通 HTTP 上游拒绝 WebSocket，避免错误目标在共用假服务时被掩盖。

`icarus.toml` 将 rela-mem 标为 WebUI 可选依赖。服务不可用只影响人物请求，不作为 WebUI 启动条件。`check-services.mjs` 用带鉴权的最小人物列表请求诊断业务连通性，输出不包含记录或凭据；诊断失败可以非零退出，与 `/health` 的进程存活语义分开。

只读请求设置 15 秒超时，并在 URL 切换时取消。`useRead` 只向当前 URL 暴露结果，旧人物/筛选响应不会覆盖新状态。同 URL 刷新可保留旧数据并明确报告刷新失败。HTTP 状态与服务错误码保留于 `RelaError`，204 不读取 JSON。

## 路由与阅读状态

| URL | 含义 |
| --- | --- |
| `#/people?q=...&kind=...&archived=true&cursor=...` | 人物列表，归档为包含语义 |
| `#/people?person=<完整 ID>&section=profile` | 人物详情；另有 relations/circles/identity 分类 |
| `#/people/circles?...` | 圈子列表，支持名称、类型、归档与游标 |
| `#/people/circles?circle=<完整 ID>` | 圈子详情 |

`person_archived=true` 允许从归档成员或工具结果读取人物，不修改原列表筛选。完整 ID 编码进地址栏；卡片只缩写展示，当前页发生缩写碰撞时延长至可区分。

列表每页 20 项，下一游标使用服务返回值，不计算总数/总页数。访问过的前页游标按查询条件保存在 `history.state.relaPages`；分类分别保留路径。筛选变化清空对应游标，刷新保留当前页和已访问前页记录。

列表打开人物新增历史条目，详情分类切换替换当前条目，关系跳人新增条目。`relaOrigin`、`relaTrail` 与 `relaDetail` 记录返回轨迹，关闭回进入前列表或圈子；无已知来源的深链接关闭落到安全列表。列表滚动、触发 ID 和焦点保存在历史状态及组件引用中。详情阅读使用公共 Modal，键盘分类支持方向键、Home/End；关闭恢复触发条目焦点。

档案当前值与单 key 历史分别分页。JSON `null` 是有效值；忘记追加墓碑，随后独立展示该 key 的历史。刷新后可在“按 key 查看字段历史”读取已忘记字段。页面不展示未提供的完整 key/精确身份绑定清单；精确身份仅按 namespace/value 解析，合法空结果与请求失败区分。

关系语句核对完整端点、other_person 与 relative_direction，再使用服务提供的 detail。缺少反向称谓时展示实际正向陈述并标注缺失，不推断亲属或称谓。编辑保留服务端规范化的端点顺序及范围；双向更新同时发送两个称谓。

## 圈子与写入

人物卡片按内容宽度 600/960px 切换一/两/三列，列宽上限 280px，由内容自然决定高度。36px 头像旁的正文按姓名/类型标签、可选别名、ID 顺序排列；助手/用户使用类型图标，其余人物使用姓名首字。类型标签与头像共享低对比色调，归档独立标识；无别名不占位，ID 使用公共无衬线字体，不设底部分栏、分割线或跳转箭头。悬停只改变背景和边框颜色。圈子卡片以 800px 为界显示一/两列，列宽上限 360px，使用内容高度。列表为空时区分筛选无结果与尚未创建，并提示对应新增入口。成员按稳定 ID 定位，姓名、角色、圈内别名与身份说明可换行。

圈子卡片复用人物卡片的 36px 图标/正文结构，名称与类型同排，其次是可选的负责人 ID 和圈子 ID。没有负责人时不渲染占位，不设分割线或跳转箭头。

首次进入列表不将焦点移到整个内容区；关闭详情后才恢复实际触发卡片。人物与圈子详情桌面宽度 860px，标题、头像、分类和正文统一使用 28px 水平内边距，手机为 20px；内部不再嵌套居中的窄容器。浅色调头部承载头像、身份信息与带铅笔图标的次级编辑操作，手机端编辑操作放入下一行。完整 ID 使用可整体点击复制的紧凑胶囊，字体沿用公共无衬线体系。人物分类左对齐，窄屏等分；档案搜索与实心添加按钮分列，移除重复的档案标题。空状态有浅底虚线容器和操作提示，字段历史查询使用折叠面板。编辑表单只使用 fieldset 的 16px gap，清除公共 Field 默认外边距，避免间距叠加。

公共游标分页仅在存在前页记录或服务报告后续页时显示，按钮采用紧凑样式。首屏空集合与单页结果不显示分页；翻页后因记录变化出现空页时，保留上一页入口，不能仅按当前项数隐藏导航。

人物/圈子阅读外框使用稳定高度 `min(760px, 100dvh - 96px)`，手机使用完整视口高度；加载与分类变化只改变内部滚动内容。列表保留数据刷新时使用公共 overlay 加载提示，不将卡片向下推。跨模块按钮边框与加载交互的复现和验证见[交互稳定性记录](../2026-10-27-interaction-stability/plan.md)。

点击当前页卡片时，人物/圈子详情以该卡片的真实记录初始化显示，并继续请求最新详情。人物档案读取可与人物详情校验并行，不先清空姓名、身份和分类。详情未完成校验或校验失败时，编辑入口与正文中的写按钮保持禁用。卡片记录仅供本次弹窗即时显示，没有添加跨人物缓存；直接访问未在当前列表中的详情仍走正常加载状态。阅读正文预留滚动条槽位，各分类和历史读取使用不占布局的加载层；所有公共加载图标延迟 180ms 显示，避免快速响应时短暂闪过。

rela REST 没有 `GET /v1/circles/{id}`。圈子深链接及刷新以每页 200 条遍历现有圈子列表定位，支持取消与重复游标检测；找到后独立分页读取成员。圈子数量大时会增加定位成本，服务端单条读取属于后续服务能力。

所有表单一次只执行一项 REST 写入，成功后重读受影响的列表/详情。成员更新保留已有 joined_at，退出产生 left 状态。人物创建只开放 human/virtual；不提供人物合并、身份重绑、硬删除或专用归档流程。

写入不自动重试。连接中断、超时、5xx 或无法解析成功响应时标记“结果待核对”，保留输入并禁用提交；用户需刷新核对后显式允许再次提交。普通冲突/校验错误保留草稿。公共导航保护覆盖离开、返回和刷新；编辑器消费顶层 Escape，避免同时关闭底层阅读弹窗。

## 对话关联与测试

`chat-app/src/relationshipLinks.ts` 只解析五个已知 relationship 工具的完整 JSON 结果，从人物、候选或关系端点提取合法稳定 ID。裁剪/无效 JSON、自由文本与其他工具不生成猜测链接。工具原始结果保留；点击进入统一人物详情，返回保留原会话，不提交消息。没有 ID 的 forget/失效结果仍只显示原结果。

浏览器测试在 `test/packages/relationship_app`，使用 `test/rela_service.py` 的 REST 形状隔离数据；工具关联在 `test/packages/chat_app/test_relationship_links.py`。开发/生产代理使用实际 Node HTTP 入口与本地假上游，启动白名单和业务鉴权诊断有独立测试。同日生产修复后已从 Windows 浏览器通过 WSL WebUI 验证真实 Gateway 只读 RPC、rela 人物卡片与阅读详情；真实业务写入、数据库持久化和模型 smoke 尚未验收，结果单独记录于交付文档。
