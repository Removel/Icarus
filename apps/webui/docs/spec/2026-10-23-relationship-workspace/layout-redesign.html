人物卡片 + 阅读式档案

这不是生产页面，也不包含真实请求。示例数据只用于验证信息密度、同名区分、详情阅读和响应式空间。

核心取舍

  • 外层完整复用记忆/知识库的管理页节奏：侧栏保留、紧凑标题、居中分类、主操作在右侧。
  • 首页采用响应式紧凑人物卡片，宽区三列、中区两列、窄区一列；头像与姓名/类型组合，无别名不占位，不再强制方形。圈子采用宽区两列、窄区一列的紧凑卡片，不展示成员统计。
  • 详情沿用弹窗，关闭后回到原列表；关系跳人时在弹窗内保留返回轨迹。
  • 档案 key 原样显示，对象/数组使用 JSON 区域，null 明确标为有效值；历史只出现在单字段上。

刻意没有放入的能力

  • 没有人物总数、总页数、任意排序、语义搜索、仅归档筛选和完整关系图。
  • 没有人物合并、硬删除、批量写入或跨请求事务承诺。
  • 当前接口不能列出某人的全部精确身份，因此详情只提供别名管理与按 namespace + value 核对身份。
  • source_ref 以文本展示，不伪装成可点击的会话来源。

可讨论的下一步

优先讨论首页卡片比例与列数、详情四个分类是否符合核对任务，以及“圈子”是否与人物同为一级分类。确认布局后再拆生产接入范围。
