## 1. 本次已经确定的决策

### 1.1 导航与页面外壳

- 复用左下角现有账户菜单；「知识库」「记忆」「人物」与「系统设置」同级。
- 点击知识库、记忆、人物，在主区域打开对应管理页；系统设置保持现有交互。
- 不增加常驻「工作台」按钮，不增加账户子菜单，也不在对话侧栏顶部或中部增加三个管理入口。
- 管理页保留对话侧栏及既有收起/展开行为，返回对话沿用 Shell 现有方式。
- 知识库、记忆的现有入口随这次导航决策迁移；不能只新增人物入口而保留重复导航。

### 1.2 人物首页

采用**响应式紧凑人物卡片网格**，优先支持浏览、辨认 Agent 认识的人。2026-10-28 根据实际截图反馈调整：原方形卡片对当前身份字段过于空旷，不再强制方形比例。

- 管理页标题为「人物」，顶部居中分类为「人物 / 圈子」，右侧主操作随分类切换为「添加人物 / 新建圈子」。
- 人物筛选区依次为姓名/别名搜索、人物类型、「包含已归档」和刷新。
- 按主内容区实际可用宽度决定列数，计入侧栏和内边距。建议网格宽度 ≥960px 三列、≥600px 两列，其余一列；P0 可据视觉验证调整阈值，保留宽区三列、中区两列、窄区一列的行为。移动端默认一列，满足内容最小宽度后可两列。
- 卡片列宽上限 280px，由内容自然决定高度；同一网格行对齐。36px 头像与身份正文横向组合，姓名和类型标签同排，随后为可选别名与简短 ID。不设分割线、底部分栏或阅读箭头，ID 沿用公共无衬线字体，不靠拉开上下间距填满正方形。
- 助手和用户使用对应类型图标，其他人物头像替代符由姓名生成，不伪造照片。类型与归档独立展示，归档标识不能覆盖人物类型。
- 姓名最多两行，别名最多两行并视觉截断；长英文可断词，无别名不渲染占位行。详情保留完整姓名与别名，不显示推测的「还有 N 个别名」。
- ID 显示首尾片段并带省略号；当前页缩写碰撞时延长至可区分，必要时完整展示。可访问名称包含完整 ID，详情可读/复制完整 ID；身份辨认不能只依赖悬停提示。
- 整卡使用单一可聚焦的详情链接，支持键盘打开；不嵌套编辑/删除按钮，不增加悬停才出现的必要操作。
- 同名是合法数据。不要用姓名作为身份或路由主键；候选项至少能通过别名和稳定 `Person ID` 区分。
- 列表只显示当前页数量和游标分页，不显示接口未提供的总数、总页数、关系数、完整度、活跃度或任意排序。
- 列表别名最多只有服务返回的前 10 项；不得宣称完整，也不得编造剩余数量。
- 「包含已归档」是包含语义，不是「仅看已归档」。
- 保留服务默认每页 20 条，不为凑齐三列改变分页或额外补数据。改变窗口/侧栏宽度只调整列数，不重置筛选、游标与选中人物；不增加列表/卡片切换控件。
- 搜索、类型或归档变化后清空旧游标栈，从首游标重新请求。上一页由已访问游标记录支持，不按页码计算下一游标；快速搜索时取消或丢弃旧响应，防止覆盖新条件。

### 1.3 人物详情

采用**弹窗阅读式人物档案**，与记忆、知识库保持列表上下文：

- 桌面为宽 860px 的居中弹窗，窄屏全屏；内部单列阅读，标题、头像、分类与正文共用 28px 水平内边距（手机 20px），不嵌套居中的窄容器，不改成固定左右分栏。
- 头部使用主题浅底色，展示姓名、类型/归档状态、完整别名、可整体复制的 `Person ID` 胶囊和带铅笔图标的次级编辑按钮；没有别名时不渲染占位行。
- 从归档候选进入详情时，对详情及支持该参数的分区请求传入 `include_archived=true`，不能列表可见但详情误报不存在。
- 详情分类固定为「稳定档案 / 关系 / 圈子 / 别名与身份核对」。这是阅读结构，不代表服务用一个聚合接口返回全部数据。
- 分类左对齐，正文不重复「稳定档案」标题；搜索与实心添加按钮分列。详情内按钮与输入框使用 8px 圆角，空状态使用浅底虚线容器及对应操作提示，字段历史查询采用折叠面板。
- 首屏空集合与单页结果隐藏分页；有前页或后页时显示紧凑按钮。翻页后的空页保留上一页，避免失去返回路径。
- 关闭详情后回到原人物列表，保留筛选、分页和滚动位置；切换详情分类不丢失列表状态。
- 从关系进入另一人物时仍留在详情中，并保留可返回上一个人物的轨迹；换人要重新加载该人的各区块，不能残留上一人的数据。
- 详情以 URL 中的完整 Person ID 与分类表达，不只靠组件布尔值。首页 URL 保存可分享的搜索/类型/归档条件；游标栈、滚动位置和浏览轨迹保存在对应历史条目或按条件隔离的页面状态中。
- 首页打开详情新增历史条目；详情分类切换使用 replace，关系跳人新增条目。返回回到上一人物或原卡片页；关闭回到进入详情前的管理页并恢复筛选、当前页、滚动和触发卡片焦点。
- 深链接直入时关闭回人物首页，不能无保护地 `history.back()` 离开应用；刷新可重读当前人物和分类。游标失效要提示并提供回首屏路径，不能渲染为空人物列表。
- 弹窗具备正确标题、焦点约束、Escape/关闭与焦点恢复；未保存表单沿用现有导航保护。

### 1.4 圈子

- 「圈子」与「人物」同为管理页一级分类。
- 一级入口与人物所属圈子只读信息保留；首页在内容宽度 800px 以上两列、以下一列，卡片列宽上限 360px。采用与人物一致的 36px 图标、名称/类型同排和紧凑 ID 结构；负责人仅在存在实际 ID 时展示，不设占位、分割线或箭头。圈子详情沿用第 1.3 节的宽度、对齐、表面层级、ID 复制与分页规范；成员采用可换行条目，不强制方形比例。
- 首期可交付真实基础只读列表，但不等于圈子布局已验收；不编造成员总数、关系数或活跃度填空。
- 当前没有独立的 `GET /v1/circles/{id}` 详情接口。从列表选择时可使用返回对象并请求成员；直达与刷新恢复方案在 P5 明确，不能默认目标必在第一页或调用不存在的接口。
- 人物详情中的「圈子」只表达当前人物的所在圈子；完整圈子管理仍归一级「圈子」分类。

## 2. 详情的信息表达契约

### 2.1 稳定档案

- 使用开放 key，不建立职业、饮食、兴趣等固定中文分类，也不把未知 key 丢弃。
- 值支持任意合法 JSON：字符串直接阅读；对象/数组用等宽、可换行的 JSON 区域；数字和布尔值正确序列化。
- active 的 JSON `null` 显示为有效空值，不能显示为「无数据」或「已删除」。
- 每项展示实际存在的 `source`、`source_ref`、记录时间；`source_ref` 默认是纯文本，不伪造会话深链接。
- 修正和忘记都作用于单个 key。忘记是追加 deleted 墓碑，不是物理删除。
- 历史入口属于具体字段，只请求该 key 的历史；不要提供全档案时间线，也不要把历史能力复制到关系。
- 档案筛选和分页使用服务真实能力。前端当前页过滤不能冒充全量搜索；尚未加载的 key 不能据此判定不存在。

### 2.2 关系

- 用查询视角下的自然语句表达，例如「王明是鱼梦的同事」，并保留方向、称谓与状态。
- 渲染前核对 `from / to / other_person / relative_direction / detail / detail_missing`，不得按返回端点顺序猜方向，不得自动补全缺失反向称谓。
- 修改正反称谓需要同时明确提交两者；失效不是物理删除，关系没有完整变更史接口。
- 不实现虚构的全量关系图、共同关键词推断或自动亲属推理。最短路径与局部关系图不属于本布局基线的必做内容。

### 2.3 别名与精确身份

- 人物详情可展示完整别名，并提供添加、移除入口；别名删除不等于删除人物。
- 别名写入使用真实的 `namespace / value / display_value` 模型，移除按 alias ID；精确核对的命名空间不能被示例选项限制为固定三种。
- 当前 REST **不能列出某人的全部精确身份**，因此不得制作身份绑定列表。
- 只提供按已知 `namespace + value` 的精确核对。`200 {"person": null}` 是合法未找到结果，不是请求错误。
- `name` 搜索不是精确身份解析。人物合并、身份重绑、归档和硬删除均需要独立产品流程，不塞入泛化「删除」按钮。

## 3. 静态稿与生产实现的边界

静态稿用于确认信息架构、密度和交互，不是可直接复制进生产的实现：

- 顶部「布局稿」工具条、设计说明弹窗、主题演示按钮及演示 Toast 不进入生产页面；生产主题沿用现有设置。
- 示例人物、别名、圈子、档案、历史、来源和时间全部是演示数据，不代表真实服务响应。
- 创建、编辑、档案修正/忘记、别名和关系操作在静态稿中只有反馈，不代表前端或后端已经接通。
- 静态稿的本地筛选、数组分页和样例关系语句不能作为数据层实现；生产必须调用真实接口。
- 视觉复用 WebUI 现有颜色、字体、间距、控件、弹窗和主题 token。HTML 中的尺寸是布局参考，不另建一套平行设计系统。
- 已采用人物包 `@icarus/relationship-app`（`packages/relationship-app/`）、根路由 `#/people`、圈子分类 `#/people/circles`，详情用 `person / section` 参数；完整 ID 做 URL 编码。已核对并落实，变动需同步文档与测试。
- 同源前缀使用 `/api/rela`，剥离前缀后请求 `/v1/...`；沿用 `ICARUS_RELATIONSHIP_ENDPOINT` 与 `RELA_MEM_API_TOKEN`。Vite 需在 Node 侧读取非 `ICARUS_` 前缀 Token，不使用 `VITE_`、客户端 define 或浏览器存储注入凭据。
- Shell 管导航/承载，人物包管类型、请求、状态与业务展示；仅复用已有公共控件，不为单一调用方新增共享业务层。

## 4. 分阶段实施任务

执行顺序为 P0 → P1 → P2 → P3；P4、P5 分别验收人物纠错与圈子管理，P6 依赖 P3，不阻塞前述交付。下方保留阶段任务，实际顺序偏离与组件合并见交付记录。P1～P3 构成首个只读交付。

阶段实施先明确行为、增加聚焦功能测试，再实现、验证和记录；纯视觉尺寸使用浏览器检查，不写仅复述 CSS 的测试。文件均相对 `apps/webui/`，明确注明仓库根或其他应用的除外。以下新增路径为实施落点，不表示文件已经存在；组件按实际复杂度拆分，不提前创建空框架。

## 5. 数据状态与失败处理

以下状态必须可区分，不能统一渲染成空白或「暂无数据」：

- 首次加载、刷新、下一页加载；空名录、搜索无结果、单页为空。
- 服务离线、鉴权失败、请求失败、请求超时。
- 详情基础信息成功但档案/关系/圈子某一区块失败；失败区块可独立重试，不清空其他已成功内容。
- 还有下一页、游标失效、筛选条件变化后重新分页。
- 零档案、零关系、未加入圈子、无别名、精确身份未找到。
- 写入冲突、部分成功、结果未知。写超时可能已经生效，`source_ref` 不是幂等键；不得自动重试后宣称只完成一次。

人物浏览不创建 Agent 会话、不触发模型。浏览器不直连 FalkorDB/PostgreSQL，不持有 `RELA_MEM_API_TOKEN`。现有 `/api/v1` 代理属于 OpenKB，不与 rela 混用。rela 离线不应阻止 WebUI 和对话打开，也不得以当前 workspace 假造人物数据隔离。

## 7. 验收标准

### 布局与交互

- 账户菜单只有一套知识库/记忆/人物入口，系统设置行为不回归。
- 保留对话侧栏及其收起/展开；桌面与窄屏不出现横向溢出。
- 首页是响应式紧凑卡片网格，人物卡片宽度不超过 280px、高度随内容自然形成，圈子卡片宽度不超过 360px；详情为阅读式弹窗；四个详情分类、关系跳人返回与列表上下文恢复符合本计划。首次进入列表不自动聚焦整个内容区；表单字段间距不与公共 Field 外边距叠加。
- 浅色、深色、键盘焦点、Escape/关闭、长姓名/别名/未知 key/大 JSON 均可读可操作。
- 至少验证 1440、1024、768、390px 与内容宽度断点前后，覆盖侧栏展开/收起并检查实际列数；增加 200% 文本缩放、同名、相似 ID、类型/归档并存，保证移动导航与浏览器返回可用。

### 数据与接口

- 同名人物不会被合并，所有详情和写入以 `Person ID` 定位。
- 搜索只是姓名/别名文本子串匹配；归档是包含语义；游标随筛选条件重置，不显示虚构总数。
- 任意 JSON、有效 `null`、deleted 墓碑、单字段历史、截断列表和空结果表达正确。
- 关系方向与称谓来自真实响应；缺少反向称谓不会掩盖关系。
- 无完整精确身份列表、无假来源链接、无未支持排序/统计/全图。
- 服务离线、鉴权失败和区块部分失败不破坏对话及其他管理页。

### 工程验证
