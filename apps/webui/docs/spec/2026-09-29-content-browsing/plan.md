# 记忆与知识：沿关系逐步探索

2026-09-29 · 内容组织设计提案。原有业务页面保持原样；独立设计实验入口：`/content-study.html`。

用户确认方向：**像逛知识空间，按内容之间的关系逐步探索。** 保留现有 Semi Universe 组件、主题和细节；改变内容的组织逻辑及展开顺序。

## 1. 核心判断

用户不需要同时面对全部记录，但也不想只看到一张孤立卡片。合适的展示单位是：**当前关注的内容，加上它附近一层有明确含义的关系。**

画面中的主次来自用户的选择：正在看的内容成为中心，来源和下一步方向形成周边节点。用户点选节点时，关注点转换，关系随之更新。信息密度取决于当前问题，而非数据库记录总数。

保留卡片组件，是为了给每个对象一个清晰的触达区域；卡片的位置承担来源、归属和去向的含义。无需靠大小随机变化、瀑布流或自由摆放营造“空间感”。

已检查 MemoryApp、KnowledgeApp、KnowledgeReader、Graph、Reading、两个 demo 模型、共享 UI、Shell 布局、功能测试和接口映射。设计实验直接使用这些示例数据和真实 Semi 控件，不重新手写一套类似的控件外观。

## 2. 三层注意力

| 层级 | 用户的问题 | 展示 |
| --- | --- | --- |
| 定位 | 我现在在看什么？ | 一个中心卡片，标题、真实内容摘录、主要阅读动作 |
| 探索 | 它从哪来？还能顺着看什么？ | 近邻节点与含义明确的连线；只展开一层 |
| 阅读／修正 | 具体内容是什么？要改哪里？ | 沿用 Semi Modal，完整内容与针对当前对象的操作 |

默认不铺出整张知识图谱。全图会让用户承担找节点、辨认连线、缩放和拖拽的工作；局部探索把这些操作换成“点一个方向，继续看”。不自动游走、不自动展开、不做悬停翻页。

## 3. 知识空间

### 固定角色，不固定内容

桌面空间中：中心为当前页面，左边为来源资料，右边为同源知识。相邻节点视觉权重低于中心，只显示识别它所需的类型、标题和关系依据。

例如，从 **Agent 分层架构** 出发：

```text
Icarus 架构说明.md ───┐                     ┌── 插件运行时
                     ├── Agent 分层架构 ───┼── Icarus
插件开发指南.pdf ────┘                     └── 架构说明摘要
       来源引用             当前关注               共同来源
```

点击“插件运行时”，它进入中心，来源收敛到“插件开发指南.pdf”，同源页面变成“Agent 分层架构”。这是一次有内容含义的移动：用户从一篇架构知识，走到同份资料支持的另一篇知识。

点击一份来源资料，它成为中心，右边展示引用这份资料的页面。此时左侧没有更上游的已知对象，可以留白并说明已经到达来源；不制造没有数据依据的节点来填满布局。

### 关系必须可解释

现有示例只有来源关系，没有语义相似度、主题聚类或推荐结果。设计实验中的边仅代表：

- 页面 → 来源：该页面引用这份资料。
- 来源 → 页面：这篇页面引用该资料。
- 页面 → 页面：两篇页面引用了至少一份共同资料，节点显示共同来源名称。

共同来源不能被标为“语义相似”或“推荐阅读”。正式接入应使用真实 page links / graph / 来源元数据。服务返回的其他关系可以扩展，但必须标出实际关系类型，不能让视觉上的连线冒充知识推理。

### 保留来路与跳转能力

上方保留探索路径，每一站都可返回；返回只回溯关注点，不创建新的一站。重复点当前对象不增加路径。再次经过同一个对象允许形成路径循环，但不会复制对象本身。

“换个起点”让不在当前近邻中的页面仍可发现，避免关系稀疏时成为死路。搜索覆盖整个当前知识库，选中结果直接把它设为关注点；无需从起点一层层猜路径。

设计实验的初始关注点是第一篇示例页面，不暗示“最重要”或智能推荐。正式产品可优先恢复用户上次位置，再提供可见起点；需要单独确认阅读历史的存储方式。

## 4. 记忆空间

记忆和知识的关系不是同一种东西。不能把不同用户的偏好放进同一个图，也不能因为两个句子有共同词汇就连接它们。

记忆的探索顺序为：

```text
所属用户 → 当前工作情境 → 已有分类 → 原始记忆 → 查看／修正
```

先选择用户与工作区，默认从该用户在当前工作区生效的记忆及其全局记忆进入。中心展示这个明确的上下文，旁边给出已有分类及一小段真实原文。点分类后，分类成为中心，右边展示其中的原始记忆，左边保留回到上下文的入口。

例如 lin 的“设计偏好”来自现有 metadata.category。它不是自动生成的人格标签。点开原句，只修改该条 ID 对应的原始记忆；不会重新总结整组或联动修改别的记录。

范围不会因视觉聚合而模糊：分类里每条原句仍显示全局／工作区。暂停和自然过期的内容单独折叠，不能混入当前生效关系。切换用户会重置分类位置，避免把上一用户的关系残留到当前视图。

已有分类不足以覆盖未来的语义记忆关系。本阶段只呈现身份、范围和分类这些真实的组织关系；从任务、会话、事件探索记忆，需要后端存在相应的关联记录后再设计。

## 5. “精致但不抢注意力”的具体约束

- 直接复用现有 Button、Select、SearchField、Modal、Status、TextArea、PageHeading、BrandMark，以及 Reading 和主题编译链。
- 沿用当前字体、主色、浅灰画布、白色内容、12 px 卡片圆角、8 px 控件圆角、36 px 控件高度与既有间距尺度。
- 只突出一个中心卡片；附近节点使用普通边界，连线低对比，不用多色关系编码、发光或背景网格。
- 左、中、右角色稳定；不会因节点个数变化把“来源”突然移到另一边。点击转换内容，不做飞入飞出或大幅缩放。
- 周边卡片承载识别信息，中心承担概要，弹窗承担长文与操作。不要在每个周边卡片上复制整套状态、来源栏和管理按钮。
- 原有底部导航、组件样式与管理功能继续保留。

大规模内容不能沿用示例的“全部近邻展开”：每类先显示少量节点，明确剩余数量，并允许筛选该关系下的对象。顺序基于稳定的来源数据或用户选择，不用未解释的推荐分数。原型数据每侧最多四个节点，因此没有实现关系分页。

## 6. 弹窗在探索中的位置

点周边节点表示“继续探索”，点中心的“阅读全文”表示“停下来读”。这两个动作明确分开，避免每次移动关注点都弹出一个窗口。

记忆原句是末端对象，点击直接打开约 560 px 的 Semi Modal，原文优先，分类、身份、范围、有效状态可核对，历史默认折叠。修正仍在同一窗口，有未保存改动时在当前窗口提示继续或放弃。

知识全文使用约 840 px 的 Semi Modal。点击来源，在同一弹窗中切换资料文本，并提供返回知识页面；返回恢复阅读位置。只提供资料级来源，不伪造段落定位。关闭后回到中心卡片，当前关注点与探索路径保留。

## 7. 手机与可访问性

窄屏无法在不牺牲可读性的情况下容纳三个方向。因此保留相同语义，改为“当前关注 → 来源／上游 → 下一步”的纵向分支，关系标签与分支线仍可见。对象用按钮呈现，可通过键盘和触摸探索，不依赖拖拽或悬停。

路径可滚动、可返回。标题与文件名可折行。弹窗正文独立滚动；用户不必滚回顶部才能结束阅读。尊重减少动效偏好。

## 8. 权衡与验证

关系探索适合发现和理解，但批量比较、删除、排序的效率可能低于表格。管理入口保持明确可达，不把批量工作强行改成图操作。对于只想找一篇内容的用户，搜索保持直接。

原型目标不是宣称效率已经提高，而是验证以下假设：

1. 用户能区分中心内容、来源、同源知识，不把共同来源理解为语义关联。
2. 点相邻节点后，能解释自己为何到这里，且能沿路径返回。
3. 找不到下一步时，能通过其他起点或搜索离开当前分支。
4. 记忆按用户隔离，按真实分类组织，修正只作用于被选中的原句。
5. 对比原版，组件质感保持一致，变化来自内容组织。
