# DeepSeek 性能设计落地对照清单

状态日期：2026-10-24（Asia/Shanghai）。

参考：[DeepSeek 网页「快」与「顺」的逆向调研](../../deepseek-performance-reverse-2026-10-23.md)。
实施入口：[WebUI 性能改造](plan.md)；结果与测试：[验证记录](plan-validation.md)。
下表章节编号均指原调研文档。

## 范围与状态口径

本轮变更限定在 `apps/webui/`，包括浏览器代码、WebUI 自有静态服务器、构建、依赖、测试与文档。
不改 Gateway、Agent、Plugin Runtime 或模型提供层。

- **本次落地**：本轮新增或明确改造的机制。
- **部分实现**：已有可用实现，但覆盖范围或粒度尚未达到调研描述。
- **原有能力**：实施前已有，本轮保留或适配，不计作新增成果。
- **未实施**：尚未实现、需要部署或接口配合，或当前没有适用场景。

后续候选项用于记录改造方向，不表示已经实现。调研中的耗时、帧率、缓存收益不作为本项目实测结论。

## 部分实现与缺口

| 设计 | 已做到 | 尚未做到 |
| --- | --- | --- |
| 增量 Markdown | 完成块复用、增长尾块解析 | 不是完整流式解析器；单个长块仍会重复解析 |
| AST 节点级渲染 | 顶层块级 memo | 每个内联 AST 节点独立复用 |
| 全面的尾部语法容错 | 表格头、围栏头、展示公式 | 未闭合强调、行内公式、`\(...\)` 等完整规则 |
| 跨块语义处理 | 保证引用、脚注正确性 | 当前出现 `[` 就保守回退整篇解析，优化覆盖面会缩小 |
| 高亮语言分包 | 整个高亮组件延迟加载 | Python、Bash、JSON、TypeScript 仍一起加载，未按语言细拆 |
| 公式渲染降级 | KaTeX 延迟加载，加载失败保留可读内容 | KaTeX/WASM 双渲染器与自动切换 |
| 状态更新隔离 | 消息和 Markdown 块隔离，稳定部分回调 | 全局 selector 订阅；未改用 Zustand/Immer |
| 性能自监控 | 历史加载耗时记录 | longtask、渲染频次异常、消息 DOM 缺失监控 |
| 首屏资源预算 | 减少初始加载内容 | 自动化体积门槛；未追求固定“2 JS＋1 CSS” |
| 历史缓存校准 | 快照先展示，服务端覆盖；同页切换沿用内存增量同步 | 服务端 MERGE/REPLACE、版本号、重置时间协议；刷新仍拉完整历史 |

尾部容错、语言包细拆、状态订阅隔离、性能监测和构建体积门槛可以继续仅在 WebUI 内实施。
持久缓存的服务端版本校准需要接口配合；当前保留全量校准以保证正确性。

## 未实施与适用性

| 设计 | 当前决定或原因 | 后续范围 |
| --- | --- | --- |
| CDN 边缘缓存、静态域与 API 域分离 | 本轮未配置 | 部署与运维，不必修改 Agent |
| HTTP/2、TLS 1.3 优化 | 本轮未调整入口协议 | 入口服务器或反向代理配置 |
| 会话预创建池、TTL、发送时 consume | 未实现，不能把原有按需 session.create 算作预创建 | 可研究复用现有接口，但会提前产生服务端会话，需处理清理与失败语义 |
| PoW Worker/WASM 预求解 | 当前没有 PoW 链路 | 不适用 |
| 鉴权预热 | 未引入新流程 | 需先确认实际等待来源和现有鉴权契约 |
| SSE 自动续流、整包补发 | 当前使用 WebSocket RPC，保留现有恢复机制 | 不复制 SSE 协议；增强恢复取决于现有接口能力 |
| 启动 5 秒后预取 TTS 解码器 | 当前朗读使用浏览器语音能力，没有对应 Opus/WASM 资源 | 不适用 |
| 五类配置并发预取 | 本项目没有相同的一组配置接口 | 不机械复制，需按真实请求依赖决定 |
| Mermaid、HTML 预览等重功能分包 | 本轮未新增这些渲染能力 | 有产品需求后在 WebUI 内设计 |
| 侧栏会话列表游标分页 | 当前仍通过 session.list 取得列表 | 真正分页需要确认或扩展服务端契约 |
| 侧栏会话列表虚拟化 | 本轮虚拟化只针对消息区 | 可纯 WebUI 实施 |
| iOS 键盘与回弹专项补偿 | 未实现 | 需要真机问题和验证依据 |
| transform 容器内 sticky 分组标题校正 | 消息虚拟列表没有对应 sticky 分组需求 | 暂无需求 |
| 接管滚轮并手写滚动量 | 保留浏览器原生滚轮，只处理跟随状态 | 未计划照搬，按实际滚动问题决定 |
| rAF → setTimeout 双阶段调度 | 当前使用 rAF 合帧 | 未计划照搬，按实测调度问题决定 |
| 全面清理高成本动画 | 未做专项审计，仍有 transition: all | 可纯 WebUI 实施 |
| SRI＋入口脚本失败错误页 | 未实现；原文也列为不建议直接照抄 | 可纯 WebUI 研究，需要构建链路支持 |
| 第三方 SDK 延迟注入与埋点总开关 | 当前没有调研中的登录、风控和埋点 SDK | 无须引入这些 SDK |
| 606 个分包与远程灰度开关体系 | 未复制 | 按真实功能和资源分布决定 |
| 限定 flushSync 仅用于路由与滚动补偿 | 未照搬其调用位置；项目已有记忆翻页 View Transition 的同步提交 | 只在必要场景使用，不为形式一致调整 |
| SSR、Service Worker、React 并发 API | 本轮未作为优化手段引入；原文也不将其认定为 DeepSeek 快的来源 | 根据独立需求决定 |

## 后续纯 WebUI 候选顺序

以下为尚未实施的后续候选，不扩展至其他应用。

| 顺序 | 候选工作 | 验收重点 |
| --- | --- | --- |
| 1 | 补齐浏览器性能测量与本地监测 | 固定负载记录冷/热启动、打开历史耗时、longtask、滚动帧间隔 p95、掉帧数与堆内存；记录环境，不对外上报原文 |
| 2 | 补全 Markdown 尾部容错，减少含链接时整篇解析回退 | 未闭合强调、行内公式与链接场景不闪烁；跨块引用和最终校准仍正确；观察解析耗时与 DOM 复用 |
| 3 | 高亮按语言加载 | 常用语言正确高亮，未知语言可读；网络中不加载未使用的可选语言包 |
| 4 | 为大量会话的侧栏增加虚拟化 | 大量会话下挂载数量受控；分组、选择、重命名、删除与键盘定位保留 |
| 5 | 审计动画属性并建立构建体积门槛 | 对实际热点处理 transition: all 等属性；保留减少动效支持；检查初始资源与重组件是否重新进入首屏 |

先补齐测量，是为了给后续优化提供同口径基线。状态隔离、iOS 补偿和其他细节再依据测量与真实问题安排，
不预设重写状态管理或自研完整 Markdown 解析器。

## 当前证据与限制

- 最大 JS chunk 从 674.31 KB 降至 392.04 KB；具体构建与资源口径见验证记录。
- 240 行会话场景初始挂载展示行少于 40，验证了消息 DOM 数量受控。
- 纯解析微基准中，完成块复用降低了解析耗时；它不等价于 UI 加速倍数。
- 尚未完成与调研同口径的冷/热启动、滚动 p95、掉帧率和堆内存对照；未测真实模型首字延迟。
- 虚拟化会卸载离屏消息，浏览器原生查找与选区仅覆盖挂载部分；完整导出使用历史数据。
- 功能测试、完整套件既有失败及基线复现记录统一维护在 plan-validation.md，不在本清单重复更新。
