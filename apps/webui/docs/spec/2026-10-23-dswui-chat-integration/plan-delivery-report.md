## 一、阶段工作概述

本阶段围绕 Icarus WebUI 的统一工作台建设与日常对话体验开展改造，重点解决页面风格不统一、会话操作不完整、图片输入体验不一致、工具与引用展示欠佳，以及开启联网后频繁触发搜索等问题。

截至报告编制时，已完成对话、记忆与知识库页面的统一外壳，以及会话管理、图文输入、按需联网搜索、异常提示和长会话渲染等工作。本轮提出的主要 WebUI 问题已完成修复，并经过相关自动化测试与浏览器检查；Rela 工作台尚未接入，保留为后续工作。

与基线相比，当前交付版本包含 65 个提交，最终差异涉及 192 个文件，其中 WebUI 147 个、Agent 33 个、Gateway 10 个、仓库根级文件 2 个。以上统计包含源码、测试、文档与运行资源，不等同于业务代码文件数量；本报告作为新增本地文档，不计入上述交付版本统计。

## 二、主要工作与完成情况

### 2.1 统一工作台与会话管理

基于 DSWUI 布局整合对话、记忆和知识库入口，统一主题、共享控件与移动端侧栏，减少不同页面之间的视觉和操作差异。

会话列表补齐重命名、浏览器本地置顶、Markdown 导出、多选与批量删除。针对重命名输入框的厚重光圈、容器高度及可编辑区域进行了调整；同时修复页面切换后下拉弹层残留、批量操作后焦点恢复不正确等问题。

新增 Agent 与模型共享设置入口，通过服务端现有配置完成读取和保存。输入框中尚未接入控制接口的“深度思考”按钮暂时隐藏，避免向用户提供无实际操作效果的入口。

### 2.2 对话内容、工具过程与来源引用

完善流式 Markdown、公式、代码块操作及消息操作，调整“思考与工具”的过程展示，使工具执行状态与正文保持一致的视觉层级，并缩小过程区域与回答正文之间的过大间距。

修复正文引用打开后的来源卡片样式与弹层定位，支持定位并滚动到所选来源。搜索过程展示实际查询、检索来源和成功抓取的页面，便于用户核对回答依据。

补齐消息队列与引导操作；“再次提问”可恢复文字和图片资源。删除当前会话或批量删除时，图片草稿同样参与未发送内容保护，避免只保留图片的草稿被直接丢弃。

### 2.3 图片输入与查看体验

依据 DeepSeek 图片上传调研，补齐文件选择、粘贴、拖入、上传进度、失败重试和取消操作，形成从输入、上传到消息展示的完整链路。

待发送图片统一使用 64 × 64 缩略图，修复单张图片预览过大的问题；移除按钮调整为右上角 18 × 18 图标，优化图标清晰度，并采用 220ms 悬浮过渡。图片悬浮使用手形光标。已发送图片支持查看器缩放与多图切换。

图片资源通过 Gateway 上传和读取，复用现有资源引用链路。当前支持 PNG、JPEG、GIF、WebP，上传上限为 20 MiB。

### 2.4 按需联网搜索与服务异常提示

调整联网搜索机制：开关开启表示允许根据问题需要检索，由规划模型决定是否需要外部资料。闲聊、翻译或稳定知识等场景可返回空计划；空计划不执行 Search/Fetch，也不生成无实际检索的搜索进度节点。

每次提交独立保存搜索偏好、本地时间和时区，避免排队期间修改开关影响已提交消息。检索资料通过动态 User Prompt 上下文提供给模型。

针对模型、Gateway、记忆服务和知识服务故障，统一整理可理解、可操作的错误提示，减少直接展示内部错误细节的情况。搜索不可用时提示原因，并继续普通回答流程。

### 2.5 渲染、缓存与资源加载优化

增加 IndexedDB 历史缓存与长会话虚拟列表，展示行达到 80 行后启用虚拟化；导出仍读取完整历史。对流式内容解析、可选渲染模块及管理模块采用分段处理或延迟加载，并在生产构建中提供 Brotli/gzip 预压缩资源。

性能验证轮次中，相同环境下最大未压缩 JS chunk 从 674.31 KB 降至 392.04 KB，ChatApp chunk 从 606.11 KB 降至 341.53 KB。上述数据反映该轮构建产物变化，不作为真实模型响应速度或所有终端流畅度的保证。

## 四、WebUI 之外的配套改动及复核边界

本轮改动以 WebUI 为主要对象，同时包含实现端到端功能所需的服务端支持。以下部分应由相应模块负责人重点复核。

| 范围 | 配套内容 | 重点复核事项 |
| --- | --- | --- |
| Agent：会话与配置 | 手动标题持久化、自动标题限长、共享配置读取与保存、引导事件关联提交标识 | 手动与自动命名并发、配置校验与写入边界、配置生效时机 |
| Agent：输入与搜索 | 可选 `request_options`、提交幂等指纹、搜索插件、时间与检索上下文、公开进度事件 | 核心输入契约兼容性、上下文等待与取消行为、其他客户端影响 |
| Gateway：协议与资源 | `session.rename`、`settings.get/update`、搜索选项校验、图片资源 POST/GET 路由 | RPC 边界、资源访问路径、文件类型及大小校验 |
| 仓库根级 | 共享设置和标题的跨应用契约、搜索密钥环境示例 | 契约与实现一致性、环境配置说明 |

未修改 Mem0、OpenKB 和 TUI 的服务端实现；WebUI 内记忆与知识库前端包的调整属于本轮范围。未修改 ReActAgent 或模型提供商图片协议，未引入数据库迁移。

逐提交影响与文件清单见[跨应用改动复核记录](plan-pr-review.md)。该记录保留了中间阶段统计；本报告采用清理后的最终范围：WebUI 之外共 45 个文件。

## 七、待完成事项与运行边界

1. **功能后续项：** Rela 工作台、凭据编辑表单及历史分支功能尚未实现，应单独安排需求与验收。
2. **搜索成本：** 开启联网后，即使最终不检索，仍存在一次规划模型调用的延迟和成本；规划失败会回退查询，降级场景仍可能搜索。
3. **共享配置：** revision 校验和文件原子替换不构成跨进程事务；运行中任务继续使用已加载配置，暂不支持跨客户端变更通知或模型热切换。
4. **图片资源：** 已做 MIME、签名与路径检查，尚未做完整图片解码或像素限制；暂存资源没有自动回收机制，浏览器移除图片不会同步删除服务端文件。
5. **长会话：** 虚拟化限制浏览器原生查找和文本选区可覆盖的消息范围；服务端历史分页尚不在本轮范围。
6. **运行环境：** Gateway 沿用本机单用户边界，浏览器通过 WebUI 同源鉴权代理访问；多租户部署需另行设计。
