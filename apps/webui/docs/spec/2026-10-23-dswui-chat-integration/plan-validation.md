# dswui 对话页接入：验收计划

创建日期：2026-10-23。状态：待执行；本文只定义检查方法和预期结果，不是测试报告。实施任务见 [执行清单](plan-execution.md)，范围与基线见 [接入评估](plan.md)。

## 1. 验证原则与准备

- 使用 pytest 功能测试和原生 assert，沿用 `apps/webui/test/` 按 source 层镜像的组织方式；不因为展示层移植另建 JS 测试体系。
- 先验证最小受影响文件，再跑受影响 WebUI 应用套件，最后做类型/构建/静态和 diff 检查。后端无改动时不机械扩大到所有后端全套。
- 聚焦行为与用户可见结果；视觉尺寸断言只用于遮挡、溢出、位置与阅读宽度等真实需求，不为每条 CSS 建镜像测试。
- 服务替身是协议/功能回归，真实代理测试验证生产入口，真实服务测试验证服务连通与数据，真实模型测试验证模型链路；四类结果分别记录。
- 记录环境、浏览器、源码基线、原有未提交修改、实际退出码；缺依赖、超时、skip 或中止不算通过。
- 基线重新运行确认已知失败；历史记录中的剪贴板 CRLF/LF 差异仅用于排查。不为过关删除断言或引入宽泛跳过。
- 后端写入仅使用独立验收环境与本次唯一标识数据。真实模型执行遵守仓库明确执行/费用授权要求。

准备清单：

- [ ] 确认 WebUI app 内 Node/pnpm 版本与依赖，使用现有 app 环境和锁文件。
- [ ] 记录浏览器渠道和预览 URL，确认 `pnpm dev` 可用；不停止未知服务。
- [ ] 构造固定示例：欢迎页、普通问答、多步工具、思考、错误、长代码、长标题、长会话。
- [ ] 测试入口不再默认依赖记忆首页；模块测试显式导航，chat RPC 替身与 memory.get_context 的响应分开。
- [ ] 记录基线失败身份与截图，确定本次新增断言和有意调整的旧布局断言。

## 5. 命令与执行顺序

以下为后续实施验收命令，本次文档编写不执行。工作目录为 `apps/webui`，Vite 预览须可用。Windows 已安装 Edge 时设置渠道；使用已安装 Chromium 时可省略。

```powershell
$env:WEBUI_BROWSER_CHANNEL = 'msedge'
pnpm test test/apps/shell/test_shell.py -q
pnpm test test/packages/chat_app -q
pnpm test test/packages/memory_app test/packages/knowledge_app -q
pnpm test
pnpm lint
pnpm format:check
pnpm typecheck
pnpm build
git diff --check
```

开发过程中先用具体文件或 `-k` 跑最小新增行为。完整阶段通过后，没有新改动或未决问题不反复重跑。对未跟踪的新文本文件单独检查格式/diff，避免 `git diff --check` 漏掉。不要用全局 formatter 改写无关文件。

服务代理检查沿用 `test/server/test_server.py`，全套 WebUI 测试已涵盖时不重复运行；新增静态资源后确认 Node 生产入口支持其 MIME 与路径。若前端调整影响了代理/入口，再额外运行针对性检查。

真实服务验证使用 `test/integration/README.md` 的隔离流程，分别记录 Mem0、OpenKB 和 Gateway。不要为了跑整套真实服务验收而修改用户服务数据或无关配置。当前 integration 用例会写入测试数据，并非纯读取。真实模型开关只在明确授权后开启；没有服务或授权时在交付记录中保留未执行项。

## 7. 恢复与失败处置

- 桌面里程碑不满足时，先修单条对话与导航链路，不以扩大后端改造解决展示问题。
- 发现必须新增接口时，记录具体缺失行为、现有协议依据和最小需求；其余不依赖部分继续完成，不能静默扩展成后端重构。
- 发布后恢复优先回切已知可用的前端构建；本期不改业务存储格式，避免要求回滚服务端会话、记忆或知识数据。
- 开发阶段只撤销本功能确认的差异，不使用 reset/clean 或整文件覆盖破坏上一轮及其他人的未提交工作。
- 失败日志只保留诊断所需数据，不记录服务 Key、Authorization 或私密聊天正文。
