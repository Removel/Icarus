## 结论与范围

可行，难度中等，主要是前端展示和交互适配。保留 Icarus 的 Gateway、会话和任务管理，移植 dswui 的对话布局、设计令牌及合适的展示组件。首期按下述范围预计无需后端改动。

建议对话成为默认首页，采用独立的全屏外观：一个会话侧栏、居中欢迎页和消息区、底部输入区、侧栏底部设置入口。对话页不再展示当前的工作台全局导航和顶栏。设置区域提供「知识库」「记忆」入口，进入现有完整页面，保留其内部布局、分类导航、弹窗、图谱和接口，并提供返回对话入口。不是把两个管理页面放进设置弹窗。

贴近 DeepSeek 指布局、颜色、间距、字号和消息视觉；发送、停止、引导、队列、工具执行仍服从 Icarus 的真实行为。品牌和提示文字使用 Icarus。

## 现状与关键差异

| 方面 | Icarus | dswui | 适配结论 |
| --- | --- | --- | --- |
| 技术栈 | React 19、Vite、pnpm workspace、Semi | React 18、Vite、Zustand、原生样式 | 在现有工程移植组件，不建立第二个 React 应用 |
| 传输 | 同源 `/rpc` WebSocket、JSON-RPC | 浏览器直连 OpenAI 兼容 HTTP/SSE | 保留 Gateway，不新增 Chat Completions 兼容后端 |
| 会话与上下文 | 服务端保存，按工作区选会话 | localStorage 历史、客户端组装全量 messages | 服务端为业务数据来源，本地只保存明确的界面偏好 |
| 流式更新 | task、step、sequence、思考、工具、完整文本 | user/assistant 消息和单次生成状态 | 保留任务与步骤身份，不能仅映射两段字符串 |
| 运行中输入 | 队列、引导、取消、未知提交结果处理 | 阻止普通发送，停止使用 AbortController | 展示组件继续调用 Icarus 原有操作 |
| 设置 | 统一主题、服务端配置与工作区 | 本地服务商 Key、模型、系统提示词 | 使用 Icarus 内容，供应商协议与 Key 管理不迁入前端 |
| 外壳 | 全局导航和会话栏并存 | 单个会话侧栏 | shell 按路由选择独立对话外观或管理外观 |

dswui 不是完全无状态的组件库：Sidebar 读 store，ChatMessageList 导入重生成和编辑操作，输入 hook 自己保存并清空草稿。因此不能只换请求 URL。应把选中的组件改为消费 Icarus 现有类型和明确回调，不为此创建通用多后端适配框架。

| 能力 | 现有依据与首期处理 |

| 欢迎页 | 可先显示临时新对话，首条发送时调用 `session.create(load_runtime: false)`；需处理创建失败与重复发送 |

| 编辑后重发、重新生成、分支 | dswui 截断本地历史后重请求，Gateway 无相应回溯操作；首期不提供，重复 submit 不等同原行为 |
| 深度思考、强度、联网搜索、模型选择 | 当前 submit 无这些控制参数；不展示无效开关，不复制供应商协议分支或用提示词冒充控制 |

## 改动边界与难点

1. `apps/shell` 管理默认入口、两种外观、主题、工作区公共上下文和返回路径；模块尽可能保持挂载。chat-app 不导入 memory-app 或 knowledge-app，通过 shell 提供的回调导航。
2. `packages/chat-app` 移植欢迎页、侧栏、输入卡片、设置壳和视觉；优先保留 `useChatSession`、`updates`、历史和任务流程。设置保留通用外观、工作区和管理页入口，移除不适用的 Key、系统提示词、清除本地聊天等配置。
3. 知识库与记忆继续使用原路由、内部布局和业务包。保留生产静态入口、认证、凭据代理与现有构建，不采用 dswui 的单 HTML 内联部署。
4. dswui 有 `:root`、`body`、`button`、`.brand` 等全局规则，会与 Semi 和当前样式互相影响。对话变量、重置和类名必须限定范围；仅按需加载 CSS 不够。body 上的弹窗、菜单和提示要单独带容器或类名及变量。管理页应做截图回归。
5. Agent 多步思考、工具、回答应保留顺序与身份，不能用单个 assistant loading 布尔值替代。流式展示统一调度，避免叠加两套打字或节流，检查代码块增高、思考展开、队列和软键盘。
6. 设置跳转先关闭弹层，再经过原有草稿保护；返回保留会话和阅读状态。当前保护允许继续编辑或主动放弃，不等于自动保存。
7. 不建议 iframe 或整体挂载 dswui App，避免双重业务状态、路由与主题；当前生产入口也禁止 iframe 嵌入。
8. 固定 dswui 来源提交，只引入实际依赖。该提交未见仓库级 LICENSE，不能自行标为 MIT；源码纳入和分发时记录实际授权与来源。DeepSeek 标志、字体、动画逐项核对；首期可用 Icarus 品牌和现有资源完成布局。

## 实施与验收顺序

1. 固定能力清单，承接现有未提交布局；先拆两种外观，接设置与返回。
2. 接侧栏、欢迎页、消息和输入，先贯通真实 Gateway 文本链路，保留历史恢复。
3. 补齐多步过程、队列、引导、停止、未知提交结果和断线恢复。
4. 完成样式与弹层隔离、浅深色、响应式、焦点管理，按固定视口对照官网参考。
5. 先跑 shell/chat 最小受影响测试，再跑 WebUI 应用测试、lint、格式、类型、build 与 diff 检查；管理页做功能与截图回归。

关键场景：sequence 去重，完整文本覆盖 delta，历史期间通知不丢失，断线不自动重复提交，执行中 Enter 排队和引导，停止后暂停队列，草稿跨设置导航保护，长代码横向滚动，思考展开不重播，手动阅读不被拉走，390/768/1280/1536px 浅深色和手机焦点恢复。`test/conftest.py` 默认等待记忆首页，切换首页时须同步改公共测试入口。

真实服务与真实模型验收分开记录；真实模型 smoke 按仓库规则在明确执行/费用授权后进行，不能把 mock 测试记为真实模型通过。
