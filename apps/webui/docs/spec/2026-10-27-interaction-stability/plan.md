# WebUI 点击与加载交互稳定性

- 日期：2026-10-27。
- 范围：公共 UI、人物与圈子阅读弹窗、记忆详情、知识库刷新。
- 背景：用户反馈多个页面按钮点击时跳动，卡片弹窗打开时闪动。

## 已确认原因

1. **按钮边框改变尺寸。** 公共样式给 Semi light 按钮设置 1px 边框，组件库的 hover/active 规则却将边框置为 0。实际“添加人物”按钮从 86px 缩到 84px，右对齐位置从 x=1338 移到 x=1340。没有发生缩放 transform；跳动来自边框盒尺寸变化。
2. **加载提示参与布局。** 公共 `LoadingIndicator` 最小高度 120px。人物列表保留旧数据刷新时仍在列表上方插入提示，卡片 y 从 214 移到 334；记忆弹窗在正文上方插入/移除提示，也会改变弹窗高度和居中位置。
3. **阅读框高度随异步内容改变。** 人物/圈子弹窗先显示加载状态，随后显示档案，内容高度变化使居中的外框重新定位。知识库已有固定阅读框高度，本次保留。

## 实施

- [x] 公共 light 按钮在 hover、active、focus-visible 下保持 1px 边框；保留颜色反馈、禁用状态和键盘焦点提示。
- [x] 公共 `LoadingIndicator` 增加 overlay 模式，绝对定位不占用正文高度；180ms 后才显示，快速请求完成时不会短暂遮罩。
- [x] 人物列表保留数据刷新、记忆详情读取/保存、已有知识库刷新使用 overlay；首次加载保留正常加载状态。
- [x] 人物/圈子阅读外框固定为 `min(760px, 100dvh - 96px)`，内容内部滚动；手机端使用完整视口高度。未对新增/编辑表单设置统一固定高度。
- [x] 新增隔离浏览器回归，持有 HTTP 响应比较加载前后坐标和大小，不连接真实业务写接口。
- [x] 完成受影响模块扩展回归和生产构建复核。

## 2026-10-28：人物卡片打开路径补充修正

用户复测确认点击人物卡片仍闪动，前述外框和按钮尺寸验证不能代表内部呈现已稳定。重新用正常动态偏好逐帧采样，确认弹窗会先显示空白姓名区与人物加载图标，再出现身份和分类，之后再显示档案加载图标。上一轮仅固定外框，未覆盖这个串行读取过程。

- 当前列表记录作为人物/圈子弹窗的初始显示值，仍继续读取服务端最新值；人物详情和档案并行读取。新增 `useRead` 初始数据参数只由人物详情调用，仍保留原有 URL 隔离、取消和重试语义。
- 详情校验期间及校验失败时禁用编辑入口和正文写按钮；关闭、阅读分类和错误重试仍可使用。未新增跨对象缓存。
- 人物各分类、字段历史与圈子成员读取改用 overlay；公共普通加载图标也延迟 180ms 显示。快请求不会绘制两个连续加载图标，慢请求继续显示状态。
- 阅读正文设置 `scrollbar-gutter: stable`，避免滚动条出现后让居中的身份区和工具栏偏移。公共 Modal 默认传递 `preventScroll`，防止焦点切换触发额外滚动。

新增回归在保留正常动态偏好的情况下检查弹窗首个绘制帧、详情响应前的身份、滚动条出现前后的头部、圈子响应前的身份以及详情失败后的只读状态。修改前新增人物和圈子即时身份回归均失败，修正后人物包及当时七项稳定性回归 **32 passed（83.15s）**。

生产构建完成后再次重启 WSL WebUI，实际 8080 页面加载 `index-GiaUnEBo.js`。逐帧点击真实人物卡片：首个弹窗帧已包含 Icarus 姓名，直到档案返回，身份区坐标与外框均未变化，加载图标全程未显示。真实页面仅只读检查，浏览器回归拦截业务请求；未写入真实业务数据或调用模型。
